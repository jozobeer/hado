# R53 入力根の走査から `.` 始まりを外す手順書（2026-09-16）（r53）
旧 `docs/plan.md` 49 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`wants.md` の 38（中）が「実験用 `.hd` が同じディレクトリにあるとビルドが落ちる（§50、R17）。`.` 始まりを読まない、などは名前空間と衝突しない範囲で」と、判断を残している。§50 はいま、入口のファイルのディレクトリ（根）とその下の**全ての**サブディレクトリにある `.hd` `.hdi` を読む。§51 はサブディレクトリの名前が `name` の字句（小文字で始まる）でなければ CLI が拒否すると定める。

実測すると摩擦は 3 つある。とくに (1) は「git 倉庫の根で Hado を検査できない」という実用上の穴である。(2) (3) は試し書きの隔離先が無いことである。

### 実測した材料

| 根の中身 | いまの `check` |
|---|---|
| `main.hd` + `.git/`（中に `config`） | 終了 1、`invalid namespace directory: .git` |
| `main.hd` + `.probe.hd`（`def broken = 1 + true`） | 終了 1、`.probe.hd` の E305 が読まれる |
| `main.hd` + `.scratch/helper.hd`（誤り） | 終了 1、`invalid namespace directory: .scratch` |
| `main.hd` + `Bad/`（空） | 終了 1、`invalid namespace directory: Bad` |
| `main.hd` + `1x/`（空） | 終了 1、`invalid namespace directory: 1x` |
| `.probe.hd` を明示して `check` | 終了 1、E305（明示したものは読まれる） |

`tests/` `stdlib/` `tools/` に `.` 始まりのエントリは無く、`invalid namespace directory` を期待する門番も無い（実測: `find` と `grep`）。したがってこの変更は既存のコーパスと門番の意味を変えない。

### 決定

- **決定 1: 入力根の走査は `.` で始まる名前のエントリを読まない。** ディレクトリなら再帰しない（中身も読まない）。ファイルなら `.hd` / `.hdi` でも読まない。ファイルとディレクトリの両方で同じ規則にする（Unix の隠し名前の慣習と同じで、覚える規則を 1 つにする）。
- **決定 2: 明示して渡したファイルは読む。** 入口は渡されたものだから、`.` で始まっていても読む（`hado check .probe.hd`）。そのファイルのディレクトリが根になったとき、根の中の他の `.` 始まりは決定 1 に従う（`hado check .scratch/main.hd` は `.scratch/` の中の普通の名前を読む）。
- **決定 3: §51 の拒否より前に外す。** `.` 始まりの名前は `name` の字句になり得ないので、名前空間として拒否するのではなく「読まない」にする。`invalid namespace directory` は `.` 以外の不正な名前（`Bad` `1x`）にだけ出る。門番を緩めない。
- **決定 4: `fmt` と `build --fix` も同じ一覧を使う。** `project::source_paths` が `collect_paths` を共有するので、隔離先は自動的に整形の対象からも外れる。明示して渡した `.` 始まりのファイルは整形する。
- **決定 5: 診断コードを足さない。** 拒否は CLI のままで、対象が減るだけである。`.` 始まりのディレクトリは名前空間として登録されないので `::` からも参照できない（§51 の字句が `.` 始まりを許さないので、そもそも書けない）。
- **決定 6: 仕様は §50 に 1 文、§51 に 1 文。** 追跡表の §50 の最初の行を伸ばし、判定器を R53 に向ける。
- **決定 7: `.` 始まりの名前を「無視する」のであって「エラーにする」のではない。** 綴りを間違えた名前空間（`Store/` のような大文字始まり）は今までどおり拒否する。無言で無視すると名前空間の誤りが静かに消えるためである。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| 根に `.git/` がある | `check` も `build` も普通に通る | 決定 1 |
| 根に `.probe.hd`（誤り）がある | 読まれない（`check` 終了 0） | 決定 1 |
| `.scratch/sub/helper.hd`（誤り） | 読まれない（入れ子も読まない） | 決定 1 |
| `.probe.hd` を明示して渡す | 読まれる（その診断が出る） | 決定 2 |
| `Bad/` `1x/` | 今までどおり拒否、`invalid namespace directory` | 決定 3、決定 7 |
| 正しい小文字ディレクトリの誤り | 今までどおり読まれる（その診断が出る） | control |
| `fmt --check` と隔離先 | 隔離先の書き換えを書かない | 決定 4 |

### 判定

`scripts/verify-r53.sh` を新設し、52 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** control を先に回す。

- 判定 53-a: 根に `.git/`（中に `config` と `HEAD`）を置いても `check` と `build` が通る。control として、`Bad/`（空）を置くと今までどおり `invalid namespace directory` で終了 1。
- 判定 53-b: 根の `.probe.hd` の誤りが読まれない（`check` 終了 0）。`fmt --check` もそのファイルを書かない（終了 0）。control として、同じ誤りを `probe.hd`（`.` 無し）に置くと読まれる。
- 判定 53-c: `.scratch/helper.hd` と入れ子の `.scratch/sub/deep.hd` の誤りが読まれない。
- 判定 53-d: 明示して渡した `.probe.hd` は読まれる（診断が出て終了 1）。`.` 始まりの根（`hado check .scratch/main.hd`）も読める。
- 判定 53-e: 追跡表・層の `r53`・corpus lock。`Bad/` と `1x/` の拒否は 53-a で測る。
- 判定 53-f: `fmt` と `build --fix` が隔離先を触らない（決定 4）。

### 許容される赤

工程 1 の直後まで 53-a〜53-d、53-f は赤でよい（走査がまだ読む）。control（`.` 無しの誤りが読まれる、`Bad/` の拒否）は最初から緑である。**R53 の終了時に許容される赤は無い。**

### スコープ外

- `hado test`（`wants.md` の 40）、任意の `def` の型表示（`wants.md` の 12）
- 設定ファイル（`.hadoignore` など）と検索パス。§50 の「設定ファイルと検索パスは無い」は動かさない
- `.` 始まりを「警告する」案（決定 7 で無言の無視に決めた）

- `fmt` と `build --fix` が隔離先を書かないこと（決定 4）
