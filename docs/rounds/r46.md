# R46 正準形の診断と `check --fix` の手順書（2026-09-16）（r46）
旧 `docs/plan.md` 42 節。実測は `docs/ledger.md`。

## 手順書

### 背景

Hado は冗長な書き方を拒否するので、診断が「どう書けばよいか」を言わないと、日々の編集では拒否が摩擦になる。正規形印字（`source_print`）は既にあり、parse → 印字 → parse の往復が緑なので、正準形を診断に載せ、局所的な書き換えを機械で当てる材料は揃っている。全 AST の再印字 formatter を先に作るとコメントを失うので、まわりの木を変えずに書ける書き換えから始める。`hado check --fix` が編集ループの入口になり、同じ一覧を将来の `hado fmt` と LSP の code action が使う。

### 決定

- **決定 1: 修正は 1 つの型にまとめる。** `Fix { code, line, col, start, end, replacement, canonical }` を `crates/hado/src/fixes.rs` が AST から導く。`start..end` はソースのバイト範囲、`replacement` はそこへ書く正準形、`line`/`col` は検査器が使うアンカーである。`hado check --fix` が適用し、`fmt` と LSP の code action は同じ一覧を共有する（§57）。
- **決定 2: 対象は E510 / E516 / E517。** 式とパターンの `Nil` / `Cons`（§47）と、`=> if | ...` の条件列（§53）。E501・E515・E507 などの書き換えは次段に送る。1 回の `--fix` は報告されたアンカーと一致する書き換えを 1 つだけ適用して再検査する（上限 16 回）。適用できる書き換えが無ければ診断を印字して終了コード 1 を返す。
- **決定 3: コメントを消さない。** 書き換えの範囲に `//` を含む `Fix` は出さない。範囲が重なるときは最も外側だけを残す。`Cons(a, Cons(b, Nil))` は 1 つの `[a, b]` になる。
- **決定 4: 診断に正準形を足す。** E510 / E516 / E517 の診断の末尾に `canonical form: <正準形>` を足す。既定の `check` / `build` / `dump-mono` はソースを書き換えない。
- **決定 5: 位置からバイトへの変換は `Span` の行・桁から行う。** `Span` は行・桁しか持たないので、ソースの行頭表と `char_indices` でバイト位置へ直す。桁は文字数である（§43 の字句）。字句の長さが要る綴り（`=>` `if` `)` と名前）だけを表で持つ。
- **決定 6: 判定器は `scripts/verify-r46.sh`。** 生成した入力に `check` → `--fix` → `build` → 実行を当て、期待値を判定器側で計算する。コメントの保存・冪等・既定の非書き換え・直せない診断での停止を測る。比較が差を検出することを control で先に確かめる。層別の full に `r46` を足す。
- **決定 7: 仕様 §57 を足す。** 整数の節は本文の末尾にだけ足す規則（AGENTS.md）に従い、§56 の後ろに置く。エラーコード表は変えない（新しいコードは無い）。

### 仕様への疑義（R46 では決めない）

- `--fix` の書き換えの単位（1 回に 1 つ）は仕様の言語意味ではない。`fmt` を入れるときに、書き換えを一括で当てるか 1 つずつかをもう一度決める。
- `Cons` の連鎖に `//` があるとき、外側の書き換えは出さず内側だけを直せる。今は報告されたアンカーが外側なのでファイルは変わらない。部分適用を許すかは頻発してから決める。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| `def f x => if \| x > 0 => 1 \| 0` | E517。`--fix` の後は `def f x \| x > 0 => 1 \| 0` | 決定 2、§53 |
| `def main = Cons(1, Cons(2, Nil))` | E510。`--fix` の後は `def main = [1, 2]` | 決定 2、決定 3、§47 |
| `if l \| Cons(x, Nil) => x \| 0` | E516。`--fix` の後は `\| [x] => x` | 決定 2、§47 |
| 範囲に `//` を含む `Cons` | `Fix` を出さない。ファイルは変わらない | 決定 3 |
| 同じファイルへの 2 回目の `--fix` | 書き換えず終了コード 0 | 決定 2 |
| 直せない診断（E501 など） | ファイルを変えず終了コード 1 | 決定 2 |
| 既定の `check` / `build` | ファイルの sha256 が変わらない | 決定 4 |

### 判定

`scripts/verify-r46.sh` を新設する。構造は `scripts/verify-r45.sh` に倣う。**入力は生成し、期待値は判定器側で計算する。コーパスのファイル名や行を埋め込まない。** 比較が差を検出できることを control で先に確かめる。

- 判定 46-a: E517。乱数の比較関数を `=> if |` の形で生成し、`check` が E517 と `canonical form:` を出し、`--fix` の後は `=> if` が無く、コメントが全て残り、`build` の実行結果が判定器の計算と一致し、2 回目の `--fix` がファイルを変えない。
- 判定 46-b: E510。乱数の `Cons` の連鎖を生成し、`--fix` の後が `[v1, ..., vn]` で、実行結果が一致する。
- 判定 46-c: E516。乱数の長さの `Cons` パターンを生成し、`--fix` の後が `[x0, ..., xn]` で、実行結果が一致する。
- 判定 46-d: 既定の `check` と `build` は拒否されるファイルの sha256 を変えない。
- 判定 46-e: 局所的な書き換えを持たない診断（E501）では、`--fix` はファイルを変えず終了コード 1 で診断を出す。
- 判定 46-f: §57 が `--fix`・E510・E516・E517・コメントに触れ、`docs/wants.md` が §57 を指し、full の層に `r46` があり、`cargo test --offline -q --test r46_fixes` が緑。

### 確認して報告（決定から）

- `--fix` が報告されたアンカー以外の書き換えを当てないこと（決定 2）
- `Cons` の入れ子で `//` があるときに部分適用が起きないこと（決定 3）
- E517 の正準形が `source_print` の印字と一致すること（決定 1）

### 中断の条件

**`--fix` が既定の `check` の診断を変えてしまう（書き換えの前後で意図しないコードが消える）なら、止めて報告せよ。**

**`Cons` の連鎖の書き換えが `[a, ...b]` の意味を変える（`b` がリストでないとき）なら、止めて報告せよ。**
