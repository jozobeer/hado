# R59 未使用の効果と handler の E513 の手順書（2026-09-16）（r59）
旧 `docs/plan.md` 55 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/bug.md` の 1 件目「未使用の効果に E513 が出ない（R32、裁定 #12）」。§37 は「効果を宣言して一度も使わなければ E513 とする」、§38 は「handler を宣言して一度も `with` に書かなければ E513 とする」と定め、§39 は未使用の判定を効果と handler にも当てるとし、§56 の表の E513 の行も「効果（第37節）と handler（第38節）にも当てる」と書いている。計画 18.5 は「E513 を effect と handler に広げる」を既存コードの変更として挙げている。実装はまだ無い。`dependencies.rs` の `Key` は値・型・契約・実装の 4 つで、`declaration()` は `Item::Effect(_)` と `Item::Handler(_)` を `None` で落とし、`item()` の効果の枝は空である。

材料の実測で、この穴は 2 つあることが分かった。(1) 診断がまったく出ない。(2) 効果の操作の型にしか現れない名前が偽の E513 になる。

### 実測した材料

- `def main = 0` の後に `effect Unused` と `once unused: Int` を置くと、無診断で終了コード 0（bug.md の例そのもの）。
- 効果と handler を置き、handler を `with` に書かない形も無診断で終了 0。
- `type Money = | Yen(Int)` を `once charge (m: Money): Void` の中だけで使い、handler の腕は `_` で受ける形は `main.hd:1:1: error[E513]: unused top-level declaration` になる。効果の操作の型を誰も見ていないためである（`Item::Effect(_) => {}`）。
- 操作を呼び、handler を `with` に書いた形（`once ask: Int` と `once ask => 1` と `def main = with H -> ask`）は終了 0 で通る。
- 未使用の効果と handler は `tests/accept/effect_forms/main.hd` と `tests/accept/again_inner_a/main.hd` にある。どちらも操作は handler の腕に**実装**されているだけで、呼ばれてはいない。効果を使ったと数える規則が「操作の参照」だけだと、この受理コーパスが E513 になって壊れる。handler の見出し（`handler A as Inner`）が効果を使うという規則が要る。
- 未使用の効果は `tests/reject/E123`・`E124`・`E308`・`E522`・`E605` にもあるが、期待するコードはどれも E513 より前の段階（構文と契約）である。
- ライブラリ検査（§39）の公開面の根には効果と handler が入っている。`library` を宣言したファイルに未使用の効果を置いても受理されなければならない。
- 未使用の判定は根からの到達で閉じる。`def unused_f = ask` のように未使用の `def` から操作を呼んでも、その `def` が根から届かないなら効果も使われていない（1 件報告なので、報告されるのは位置の早い方）。
- `inference_groups` は `declaration()` の鍵をそのまま使って型推論のまとまりを作る。効果と handler を鍵に足すとまとまりの形が変わる。

### 決定

- **決定 1: `Key` に `Effect(String)` と `Handler(String)` を足す。** `declaration()` は `Item::Effect` を `effect.span`、`Item::Handler` を `handler.span` で返す（§56 の表の E513 の行の「未使用の宣言の先頭」）。
- **決定 2: 効果を使ったと数える形は 2 つ。** (a) その効果の操作の名前が値として参照される（操作の呼び出しは無修飾の名前である）。操作の名前から効果の鍵への表を作り、名前の参照を効果の参照に読み替える（constructor の表 `constructors` と同じ形）。(b) `handler X as Y` の見出しが効果 `X` を指す。受理コーパスがこの規則を要求する。
- **決定 3: handler を使ったと数える形は `with` に書くこと。** `NodeKind::With` の handler の名前は自由名でも子でもないので、`expression` に枝を足して明示的に参照する（§38）。
- **決定 4: 効果の参照には操作の型を入れる。** `Item::Effect` の枝で操作の引数の型と戻り型を `type_expression` で辿る。効果が使われれば、その操作の型に出る名前も到達で使われる（bug.md の 2 つ目の穴が閉じる）。
- **決定 5: 到達は今までどおり根から閉じる。** 未使用の `def` からの参照は効果を救わない。報告は 1 件で、位置の早い方になる。
- **決定 6: ライブラリ検査では効果と handler を公開面の根にする**（§39）。根に足した宣言は参照されなくても E513 にならない。
- **決定 7: 名前で数える（ディレクトリで分けない）。** 同じ操作名を 2 つのディレクトリの効果が宣言していても、参照が 1 つあれば両方を「使った」と数える。偽の E513 を出さない側に倒す。ディレクトリごとの精密化は今回の射程の外である。
- **決定 8: `inference_groups` の鍵の集合は変えない。** 効果と handler はグラフには入るが、まとまりには入れない（型推論の順序を動かさない）。
- **決定 9: 効果の名前が型や効果行に現れれば使ったと数える。** 材料の実測で `tests/reject/E522` と衝突したため、当初の「行に現れるだけでは数えない」を差し替えた。このファイルは効果を行に書くだけで操作を呼ばず、期待する唯一の欠陥は行の重複の E522 である。行を数えないと、同じ段階の E513 が先の位置（効果の宣言）に出て期待を覆う。

### 期待値の根拠

| 形 | 診断 | 根拠 |
|---|---|---|
| 効果を宣言して操作を呼ばず handler も無い | E513、`effect` の先頭 | 決定 1・2、§37 |
| handler を宣言して `with` に書かない | E513、`handler` の先頭 | 決定 1・3、§38 |
| 操作を呼ぶ（handler は `with` で使う） | 受理、実行値は判定器側の値 | 決定 2(a)、§37 |
| 効果の操作の型にだけ現れる型 | 診断なし（型は使われる） | 決定 4、§39 |
| 未使用の `def` から操作を呼ぶ | E513 1 件、位置の早い方 | 決定 5、§39 |
| ライブラリの未使用の効果と handler | 受理（公開面の根） | 決定 6、§39 |
| 署名の行に効果が現れ、操作は呼ばれない | 診断なし（行が効果を使う） | 決定 9、§37、`tests/reject/E522` |
| 2 つのディレクトリが同じ操作名を宣言し、片方だけ呼ぶ | 診断なし | 決定 7 |
| prelude の効果（`Error` など） | 診断なし（prelude は免除） | 決定 1、§39・§55 |

### 判定

`scripts/verify-r59.sh` を新設し、58 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で生成から計算する。** control を先に回す。

- 判定 59-a: 未使用の効果。空行と字下げを生成し、診断が 1 行で `error[E513]`、アンカーが `effect` の先頭。効果の 2 行を除いた同じプログラムは受理（control）。
- 判定 59-b: 未使用の handler。アンカーが `handler` の先頭。`with H -> ...` を足した形は受理で、実行値が判定器側の値と一致。
- 判定 59-c: 操作の参照。操作を呼ぶ形は受理で実行値が一致。効果の操作の型にだけ現れる `type` は診断なし（bug.md の 2 つ目の穴）。
- 判定 59-d: ライブラリ。`library` を宣言したファイルの未使用の効果と handler は受理。同じ 2 つを entry ファイルに置くと E513。
- 判定 59-e: prelude。効果を 1 つも宣言しない `main` は受理。prelude の効果を使わない形も受理（免除）。
- 判定 59-f: 到達。未使用の `def` から操作を呼ぶ形は E513 が 1 件だけで、位置の早い方（効果）を指す。
- 判定 59-g: 1 件報告。未使用の効果を 2 つ置いても診断は 1 行で、位置の早い方。
- 判定 59-h: 書き換えなし。E513 だけのファイルに `check --fix` と `fmt` を当ててもバイト列が変わらず、`check` の終了コードは 1。
- 判定 59-i: 仕様・追跡表・層・wants・bug.md と corpus lock。

### 許容される赤

- `lint-docs.sh` の「最新のラウンドの台帳の節がある」。台帳を書くまで赤である。

### スコープ外

- ディレクトリごとの操作名の精密な解決（決定 7）。
- 効果の名前が現れる場所の網羅（型・効果行・署名は数える。`implement` の見出しなど、型として綴られない場所は今回の射程の外）。
- `with H -> rest` の本体が `H` の効果を使わないとき、`main` に効果が残って E706 になる既存の振る舞い（仕様への疑義に書く）。
- `handler` の中の腕の操作名を「操作の参照」と数えるかどうか（腕は実装であって参照ではない。§38 の「全ての操作を実装」で効果は使われる）。
- E513 のメッセージの分化（今は未使用の `def`・`type`・契約・実装と同じ `unused top-level declaration`）。

### 確認して報告

- prelude の効果と handler が免除のままであること（`.skip(prelude_items)`）。
- 受理コーパスの効果と handler がすべて「使われた」と数えられること。
- 拒否コーパスの期待するコードが変わらないこと。E513 と同じ冗長の段階に E522 があり、`tests/reject/E522` は決定 9 の差し替えで期待どおりになった（実測）。

### 中断の条件

- 受理コーパスか既存の門番が、効果を使いと数える規則の解釈で赤になり、仕様の文だけでは解けないとき。仕様を変えずに報告する。
- ライブラリの公開面の根の規則（§39）と実装が食い違い、どちらが正か決められないとき。
