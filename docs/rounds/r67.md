# R67 受理コーパスの実行確認の手順書（2026-09-16）（r67）
旧 `docs/plan.md` 62 節。実測は `docs/ledger.md`。

## 手順書

### 背景

依頼の優先順位 3「check は通るが実行できない、をなくす」は、`docs/bug.md` の 1 件（効果行付きの関数値。R61 で閉じた）だけでなく、**門番の穴**の問題でもある。受理コーパスは検査（と型の印字）で確かめられているが、実行は誰も確かめていない。

### 実測した材料

- `grep -rn "'run'\|'build'" scripts/verify-m2.sh scripts/verify-m3.sh scripts/verify-m4.sh scripts/verify-m5.sh` は 0 件。受理コーパスを走らせる門番は無い。
- `find tests/accept -name "expected*"` は 0 件。期待出力を持たないので、走らせても比べる先が無い。
- コーパスは `tests/accept/*/main.hd` の 109 件（`ls tests/accept | wc -l`）。
- 直前の全走は `TALLY: 3679/3679 passed; red: none` で、109 件すべて `check` は通っている（`verify-m2.sh`）。
- `hado build -o <path> <file>` と `hado run <file>` は §58 で決まっており、`run` は終了コードをそのまま返す（門番 r48 / r54 が固定）。

### 決定

1. `scripts/verify-r67.sh` を新設し、`tests/accept/*/main.hd` の各件について次を確かめる。
   - `check` が終了コード 0 なら、`build` も終了コード 0 でなければならない（**これが優先順位 3 の主張そのもの**）。
   - `build` が 0 なら、実行して終了コード 0 で終わらなければならない（シグナル死は赤）。
   - `build` が `main` の不在だけで失敗した件は、走らせずに飛ばす（型だけの受理ファイルを許すため）。
2. 判定器に件数や名前を書かない。件数は `ls tests/accept` の実数から導き、走らせた本数と飛ばした本数を報告に出す。
3. 実行は一時ディレクトリに出力し、入力の隣に書き残さない（§58 の出力先）。

### 期待値の根拠

| 何を | どう測るか |
|---|---|
| check が通るのに build が落ちる件 | `check` 0 かつ `build` ≠ 0 で赤。落ちた件の診断を報告に出す |
| build は通るのに実行が落ちる件 | `build` 0 かつ実行の終了コード ≠ 0 またはシグナルで赤 |
| 型だけの受理ファイル | `build` の診断が `main` の不在のときだけ飛ばす |
| コーパス全体 | 走らせた本数 + 飛ばした本数 = `ls tests/accept` の実数 |

### 成果物

- `scripts/verify-r67.sh`、`scripts/lib/gate-tiers.sh`（core か full に r67）、`docs/ledger.md`。

### 工程

1. この節を書いてコミットする（`docs:`）
2. 門番を書いて層に登録し、赤を測る（`test:`）。赤が出なければ、それは「穴が無い」という実測なので、そのまま緑として残す
3. 赤が出たら、1 件ずつ原因を切り分けて直す（`fix:`）。check と build の食い違いは実用性の穴なので、`docs/bug.md` に書く
4. 台帳を書き、全走と `cargo test` と `lint-docs` を回して報告する（`docs:`）

### 判定

- 67-a 109 件のうち `check` が 0 の件はすべて `build` が 0（赤が 0 件）。
- 67-b `build` が 0 の件はすべて実行して終了コード 0（シグナル死 0 件）。
- 67-c 飛ばした件は `main` の不在の診断だけで、その本数をログに出す。
- 67-d 走らせた本数 + 飛ばした本数 = コーパスの実数。
- 67-e 層と台帳。

### 許容される赤

- 手順 2 の時点で 67-a / 67-b が赤いこと。それがこの門番の目的である。
- 67-c / 67-d / 67-e は緑のはずである。

### スコープ外

- 受理コーパスへの期待出力の追加（コーパスは既定でロック。`tests/corpus.sha256` を実装の工程で更新しない）。
- 依頼の残り（E512 の書き換え、`tools/gates/main.hd` の継続運用、終了コード）。赤が出たらその 1 件だけを直し、他は `docs/wants.md` に残す。

### 確認して報告

- `main` の不在の診断にコードが付いているか。付いていなければ文面で判定するので、その旨を報告に書く。
- 実行の上限時間（1 件あたり）。無限ループの受理ファイルがあればこの門番が止まるので、`timeout` を置く。

### 中断の条件

- `build` が 0 でない件が多数あり、原因が 1 つの欠陥にまとまらないとき。
- `main` の不在と他の失敗が文面で区別できないとき。
