# R62 `_` の fallback と Boolean 分岐の正準形の手順書（2026-09-16）（r62）
旧 `docs/plan.md` 58 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/wants.md` の 1「冗長の診断に正準形を出す」（高）。R46 / R47 / R57 が E510 / E516 / E517 / E515 / E501 / E507 / E508 の書き換えを入れ、`check --fix`・`hado fmt`・`build --fix` が `crates/hado/src/fixes.rs` の同じ表を共有している（§57、`docs/rounds/r46.md`・`docs/rounds/r47.md`・`docs/rounds/r57.md`）。残りは未使用（直さないと決めている）と、形が局所でない E502 / E503 / E504 / E506 / E511 / E512 / E520 である。

このうち §24 と §29 は正準形を仕様に明記している。§24 は「Bool の値を分岐する形はこの 1 つに限る」として `if condition => yes | no` を挙げ、Bool リテラルの pattern 分岐と腕が 1 本だけの条件列を E520 とする。§29 は「fallback の canonical form は `| default`」と書く。この 2 つは形が局所なので、残りと同じ表に載せられる。

### 実測した材料

リポジトリルートで、その場で書いたプログラムを `cargo run --offline -q -- check` に渡した。

| 書いた形 | いまの出力 |
|---|---|
| `def f (b: Bool): Int => if b \| true => 1 \| false => 2` | `main.hd:1:25: error[E520]: use a Boolean branch instead of Boolean pattern arms or a single condition arm` |
| `def f (b: Bool): Int => if b \| true => 1 \| 2`（fallback） | 同上、`main.hd:1:25` |
| `def f (b: Bool): Int => if \| b => 1 \| 2`（腕が 1 本） | `main.hd:1:1: error[E517]: write condition arms directly after the function parameters; canonical form: def f (b: Bool): Int \| b => 1 \| 2`（E517 が先に当たる） |
| `type T = \| A \| B` と `if t \| A => 1 \| _ => 0` | `main.hd:2:38: error[E503]: use a fallback instead of a catch-all underscore pattern` |
| 同じで `\| _ => // why` のあとに改行して本体 | 同上、`main.hd:2:38`（書き換える範囲の外にコメントがある） |
| `def f (b: Bool): Int => if b => 1 \| 1`（E502） | `main.hd:1:25: error[E502]: identical branch results at 1:33 and 1:37`（枝の位置を本文に埋めている） |
| `def f (n: Int): Int => if n \| x => x`（E512） | `main.hd:1:31: error[E512]: top-level variable patterns are forbidden` |

射程から外すもの（実測のうえで）。

- E502: 枝が同じでも条件が効果を持つと条件を消せない。正準形にするには条件の純粋性が要る。本文は既に 2 つの枝の位置を持っている。
- E504 / E506: 束縛の改名が要る（`docs/rounds/r61.md`までの 3 つの書き換えは名前を増やさない）。
- E511 / E512: 腕の文脈（他の腕と scrutinee の型）が要る。
- 未使用の auto-fix（`docs/wants.md` の「足さない」に決めている）。

§24 の除外も対照として測る。`Some(true)` と、条件列が 2 つ以上の pattern 分岐の Bool リテラルは E520 の対象外である。

### 決定

1. E503: `| _ => body` の `_ =>` を消して `| body`（fallback）にする。§29 の canonical form そのものである。
2. E520: `if b | true => x | false => y` と `if b | true => x | y` を `if b => x | y` にする。§24 の canonical form そのものである。腕が 1 本だけの条件列（`if | b => x | y`）は、§24 が E520 とする形のうち、条件の位置が腕でないので同じ書き換えでは表せない。材料の 3 行目のように E517 が先に当たる位置も多い。今回はこの形の書き換えは出さず、E520 の残りとして報告する。
3. どちらも `crates/hado/src/fixes.rs` の表に載せる。新しい仕掛けは足さないので、`check --fix`・`hado fmt`・`build --fix` が自動で同じ書き換えを使う（§57、§58.1）。
4. 診断の本文は変えない。`canonical form: <正準形>` は既存の仕掛け（`project.rs` の `hint`）が足す。
5. 書き換えの範囲に `//` を含めない（§57 の規則）。E503 の削る範囲は `_ =>` だけなので、後ろのコメントは残る。
6. 仕様は §24 と §29 に書き換えの文を足し、追跡表に R62 の門番を載せる。

### 期待値の根拠

| 入力 | 期待 | 根拠 |
|---|---|---|
| `if b \| true => 1 \| false => 2` | `if b => 1 \| 2` に書き換え、診断に `canonical form:` を出す | §24 の canonical form |
| `if b \| true => 1 \| 2` | `if b => 1 \| 2` | 同上 |
| `if t \| A => 1 \| _ => 0` | `if t \| A => 1 \| 0` | §29 の canonical form |
| `Some(true)` | E520 を出さない | §24 の除外 |
| 条件列が 2 つ以上の pattern 分岐の Bool リテラル | E520 を出さない | §24 の除外 |
| `hado fmt` のあと | 変わらない（冪等） | §57・§58.1 |

- 62-a E503: 診断が `canonical form: | 0` を出し、`check --fix` が 1 回で fallback にし、`hado fmt` が一括で直し、直したソースが受理される。
- 62-b E520: 2 つの形を正準形にする。`--fix` と `fmt` の両方で測る。
- 62-c 除外: `Some(true)` と 2 条件列の Bool リテラルには E520 を出さない（対照）。
- 62-d コメント: `_ =>` の後ろのコメントが残る。書き換えの範囲に `//` を含む形では書き換えを出さない。
- 62-e 冪等: `hado fmt` を 2 回当てても 2 回目は何も変えない。
- 62-f 既存の書き換え: E501 / E507 / E508 / E510 / E515 / E516 / E517 の門番（R46 / R47 / R57）が緑のまま。
- 62-g corpus lock: `sha256sum --strict --status -c tests/corpus.sha256`（`stdlib/` を触らないのでハッシュは変わらない）。

### 追記（実装中に分かったこと）

E520 の書き換えはこのラウンドでは入れられなかった。`crates/hado/src/fixes.rs` の書き換えは `branch_range` で式の範囲を取るが、これは `ast.branch_spans` に載っている枝の位置でしか働かない。E520 の形は引数や `let` の値など枝でない位置にも現れ、その場合は式の終わりの位置が AST に無いので範囲を作れない。E503 は `_` と `=>` の 2 つのトークンから範囲を作れるので、こちらだけを入れた。

そのため門番の判定は次の 6 つになった。62-a E503 の正準形と `check --fix` と `hado fmt`、62-b `_ =>` の後ろのコメントが残ること、62-c §24 の除外が受理され規則そのものは残ること、62-d 既存の書き換えと一括の settle、62-e 仕様と追跡表と層、62-f corpus lock。実装前の赤は 62-a と 62-d で、E520 の書き換えは次に回す（式の終わりの位置を AST に持たせるのが先である）。
