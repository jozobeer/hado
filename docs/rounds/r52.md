# R52 `hado fmt` と `build --fix` を入れる手順書（2026-09-16）（r52）
旧 `docs/plan.md` 48 節。実測は `docs/ledger.md`。

## 手順書

### 背景

R46・R47 が §57 の局所的な書き換え（E501 / E510 / E515 / E516 / E517）を作り、`hado check --fix` が 1 回に 1 つ当ててやり直す。`crates/hado/src/fixes.rs` の `fixes(source)` は**ソース 1 つ分の書き換えを全部**返すが、`check --fix` は報告された診断のアンカーに一致する 1 つだけを使う。`wants.md` の 11 は `hado fmt`（正規形印字、`--check` を門番にできる）と `build --fix` を「残り」として挙げ、`docs/rounds/r46.md`は「`--fix` の書き換えの単位（1 回に 1 つ）は仕様の言語意味ではない。`fmt` を入れるときに、書き換えを一括で当てるか 1 つずつかをもう一度決める」と、判断を R52 に残していた。R52 はこれを決めて入れる。

### 実測した材料

書き換えを持つコードを拒否コーパスから `// error:` のヘッダで選ぶと 5 件（E501 / E510 / E515 / E516 / E517 が 1 件ずつ）。この 5 件で `hado check --fix` を走らせると、5 件とも終了 0 で、そのあとの `hado check` も 5 件とも終了 0（受理へ変わる）。`hado fmt` はまだ無い（終了 2、usage）。

`fixes(source)` が返す書き換えは、いずれもソースのバイト範囲と置換文字列で、範囲に `//` を含むものは出さず、重なるものは外側だけを残す。したがって**一括で当てても意味を変えず、コメントも消さない**。置換は字句と AST だけで決まり、検査器の判定には依存しない。

`source_print::canonical_program` は全体を正準形に印字できるが、コメントを落とす。今は往復の試験だけが使い、CLI には繋いでいない（`docs/rounds/r46.md`の判断）。

### 決定

- **決定 1: `hado fmt [--check] <file.hd>` を足す。** 入力根のソース（§50）を対象に、§57 の表の書き換えを**一括で**当てる。
- **決定 2: 書き換えは尽きるまで繰り返す。** 1 回の走査で当てられるものを全部当て、また走査する。上限は 64 回で、超えたら診断して終了 1（入れ子の `let` は 1 回に 1 つしか畳めないので、深さの回数だけ要る）。
- **決定 3: 既定は書き込む。** 変更したファイルごとに `fmt: <入力根からの相対パス> (<n> rewrites)` を標準出力に出す。1 つも変わらなければ何も出さず終了 0。
- **決定 4: `--check` は書かない。** 変わるファイルごとに `fmt: <相対パス> is not canonical (<n> rewrites)` を出し、1 つでもあれば終了 1。全部正準形なら何も出さず終了 0。門番に使える。
- **決定 5: `fmt` は検査をしない。** 型の検査もしないし、書き換えを持たない正準形違反（E507 / E508）の報告もしない。`fmt` の関心は書き方だけである。残る違反は `check` が報告する。`fmt` は速い（字句と AST だけ）。
- **決定 6: `check --fix` の単位は変えない。** 報告された診断のアンカーに一致する 1 つを当ててやり直す、という §57 の振る舞いはそのままにする。`fmt` は「診断を待たずに書ける書き換えを全部書く」点で別の道具である。同じ `fixes(source)` を共有する。
- **決定 7: `build --fix` を足す。** 作る前に `fmt` と同じ一括整形を当ててから読み直して作る。`--fix` が無い `build` は今までどおりソースを書き換えない。
- **決定 8: 仕様は `## 58.1. 正準形への一括整形` を §58 の直後に足す。** §58 の命令一覧に 2 つを足し、§57 に「同じ表を一括で当てるのは §58.1」の 1 文を足す。
- **決定 9: レイアウト（空白と改行）は R52 では正規化しない。** 正規形印字で全体を書き直すとコメントが落ちる。コメントを保ったまま書き直す設計が決まるまで、`canonical_program` は CLI に繋がない。
- **決定 10: 対象は入力根のソース全部。** 入力の隣だけでなく、§50 が読む下位ディレクトリのファイルも直す。`check --fix` が診断のファイルを直すのと同じ範囲で、名前の付いた 1 ファイルに限らない。

### 仕様への疑義（R52 では決めない）

- 一括適用は、検査器が報告しない（前の診断に隠れた）書き換えにも届く。書き換えは意味を変えないので安全側だが、「診断に出ていないものを書き換えてよいか」は言語の意味の問題ではなく道具の立場の問題である。審査の指摘が欲しい。
- `fmt` の終了コードは「整形できたか」だけを表し、「正準形になったか」は表さない。E507 / E508 の書き換えを足すときに、`fmt` が「直せなかった違反」を報告すべきかを決める。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| 書き換えを 1 つ持つ拒否コーパス | `fmt` の後 `check` が終了 0、`check --fix` と同じバイト | 実測（5 件とも） |
| 正準形のファイル | `fmt` は何も出さず終了 0、`--check` も終了 0 | 書き換え 0 件 |
| 正準形でないファイル | `--check` は `not canonical` を出して終了 1、ファイルは不変 | 決定 4 |
| 2 回目の `fmt` | 何も出さず終了 0（冪等） | 決定 2 |
| 型の誤り + 正準形違反 | `check --fix` は変えず、`fmt` は変える | 決定 5、決定 6 |
| `build --fix` | ソースが正準形になってから作られる | 決定 7 |

### 判定

`scripts/verify-r52.sh` を新設し、51 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** 拒否コーパスのファイル名は埋め込まず、`// error:` のヘッダから選ぶ。control を先に回す。

- 判定 52-a: 書き換えを持つ拒否コーパス（ヘッダから選ぶ）で、`fmt` の結果が `check --fix` の結果と同一バイトで、`fmt` の後は `check` が終了 0。`fmt` の出力の行が相対パスと個数を持つ。
- 判定 52-b: 型の誤りと正準形違反を 1 つずつ持つ生成入力で、`check --fix` はソースを変えず、`fmt` は変える。`fmt` の後も `check` は赤（型の誤りは残る）。
- 判定 52-c: `--check` はファイルを変えず、`not canonical` を出して終了 1。正準形のファイルでは何も出さず終了 0。`fmt` は冪等。
- 判定 52-d: §50 の範囲。入力の隣の下位ディレクトリのファイルの違反も直り、相対パスで出る。
- 判定 52-e: `build --fix` はソースを正準形にしてから作り、実行できる。`--fix` 無しの `build` はソースを変えない。
- 判定 52-f: 文書（§58.1 と追跡表と wants）・層の `r52`・corpus lock。
