### 決定

- **決定 1: `log` は `effect Io` の `once` とし、String と改行 1 つを stdout へ書く。**
  - 宣言は `once log(contents: String): Void {Error}`。既定実装は `IoDefault` の `def` に置く（R37 決定 1 の経路。0 引数の操作は `definition_reference`、1 引数以上は `specialize_function` + `call_direct`）。
  - 本体は `let status = __io_log contents -> if status == 0 => () | raise { message = io_failure_message status }`。status は 0 成功 / 4 失敗で、4 は `io_failure_message` の既定腕により `"IoFailure"` になる。**`io_status_from_errno` は使わない**（EPIPE・ENOSPC が `PermissionDenied` などに化ける）。
  - C は `int64_t hado_io_log(const HadoString *contents)`。`fwrite` で contents、`fputc('
')`、`fflush(stdout)` の 3 つを 1 つの status に畳む。**`print_failed` は触らない。** log の失敗は言語の `Error` で、利用者の `handler Error` が捕まえられる。終了コードは、捕捉されなければ `main` の raise 経路（stderr と 1）が、捕捉されても `main` 末尾の `check_stdout`（R29）が決める。
  - **R29 の再考:** SIGPIPE の無視と EPIPE の扱いは変えない。log の EPIPE は status 4 → `Error` になる。§54 の終了コードの二値も変えない。
- **決定 2: `String.trim` は ASCII の空白 6 種（SPACE 0x20、TAB 0x09、LF 0x0A、VT 0x0B、FF 0x0C、CR 0x0D）を両端から除く。** C の `__string_trim` で実装する。
  - **理由:** CR は §5 のエスケープに無く hado のソースに書けず、char のコードを取る intrinsic も無い。hado 側だけでは CRLF の CR を除けず、利用者に回避手段も無い。1 つの C 関数でこの穴を塞ぐ。
  - **バイト単位で除いてよい。** 除く 6 種は ASCII で、UTF-8 の継続バイトは 0x80 以上なので、文字（Unicode スカラ値）単位の除算と結果が一致する。
- **決定 3: `String.join(values: String List, separator: String): String Pure`。** `[]` は `""`、要素 1 つはその要素、区切りは要素の間だけに置く。hado で書く。
- **決定 4: `Int.abs` / `min` / `max` は hado で書く。** `abs` は `if value < 0 => -value | value`。**i64 の最小値では反転が表現できないので、その値自身を返す**（`ineg` の wrap）。
- **決定 5: `List.head` / `nth` / `take` / `drop` は hado で書く。** 腕の深さを 1 に保つため、判定と構造を交互再帰の helper に分ける（`nth` → `nth_from` ↔ `nth_more`、`take` → `take_from` ↔ `take_more`、`drop` → `drop_from` ↔ `drop_more`）。意味は次とする。
  - `head []` は `None`、`head [value, ...]` は `Some(value)`。
  - `nth` は index が負か長さ以上なら `None`。
  - `take` は count ≤ 0 で `[]`、count ≥ 長さで全件。
  - `drop` は count ≤ 0 で全件、count ≥ 長さで `[]`。
- **決定 6: `Int` と `List` の新しい member はコーパスの item を増やさない。** 拒否形が存在しない（全域）ので、coverage は `scripts/verify-r43.sh` が持つ。`String.join` / `trim` は既存 item `String 操作` の受理 1 本、`log` は `Env と Io` の受理 1 本で覆う。**`scripts/verify-m1-corpus.sh` の item の免除の一覧は変えない**（緩めの変更を避ける）。
- **決定 7: 版と tag は動かさない。** `docs/spec.md` と `docs/spec-coverage.md` の版は `v0.3.1` のまま（`verify-r42.sh` が固定している）。tag は R44 以降で判断する。
- **決定 8: `scripts/verify-r37.sh` と `crates/hado/tests/r37_world.rs` を追随させる。** `Io` の操作が 4 から 5 になるので、handler の腕に `once log _ => ()` を足し、既定実装の照合に `log` を足す。`scripts/verify-r37.sh` の「操作を 1 つ落とすと E605」は 5 通りに増える（**緩めではなく強化**）。
- **決定 9: 構造の門番は `scripts/verify-r42.sh` のまま残し、R43 の挙動の門番を `scripts/verify-r43.sh` として新設する。** R39〜R42 は文書のラウンドだったので番号を付け替えたが、R43 は言語のラウンドなので r9〜r38 と同じく自分の門番を足す。`scripts/lib/gate-tiers.sh` の full に `r43` を足す。

### 仕様への疑義（R43 で判断する。§5 と §54 と §55 が定めていない）

- **`Int.abs` の i64 最小値。** §5 は Int の演算の wrap を定めていない。決定 4 はその値自身を返すとし、§55 に明記する。
- **`log` の失敗と §54 の関係。** §54 は「印字が失敗したら終了コード 1」を `main` の値の印字について定める。決定 1 は log の失敗を捕捉可能な `Error` とし、終了コードは §54 の経路が決めるとする。R29 の申し送りへの回答である。
- **`trim` の空白の集合。** §55 は定めていない。決定 2 で ASCII の 6 種とする。全角空白（U+3000）は除かない。
- **`String` は文字（Unicode スカラ値）の列なのに trim の実装はバイト単位。** 決定 2 の理由のとおり結果は一致するが、実装の単位と仕様の単位が違うことを記録する。
- **`log` が prelude の操作名になる。** §37 により、以後の利用者の `def log` と `effect Foo` の `once log` は E205 になる。既存の記述に無いことは実測した。

### 判定

判定 43-b: `log` の正常系。python3 が生成した String（空・ASCII・`
` `\t` `"` `\` を含む・マルチバイト UTF-8・長い）を `log` して `main` が値を返す形を build して実行し、stdout が `文字列 + "

判定 43-d: `String.trim` と `String.join`。trim は 6 種の空白の全部、全角空白（除かない）、内部の空白（除かない）、空、空白だけ、CRLF、マルチバイト隣接を決定的に含める。join は空リスト、要素 1 つ、要素の値が空文字列、区切りが空文字列、区切りが要素に現れる形、マルチバイトを含める。期待値は python3 から導く。
