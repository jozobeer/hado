# R56 E305 に期待型と実型を載せる手順書（2026-09-16）（r56）
旧 `docs/plan.md` 52 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`wants.md` の 3（高）「E305 に期待型と実型を載せる。`--print-type` はいま `main` だけ」の前半。R55 で後半（任意の `def` の型表示）を閉じたので、残りは診断である。計画の優先順位 1 が「正準形の拒否を"修正可能な体験"にする」と言い、その本文に「診断に正準形・関連位置・期待型/実型がなければ強みが日々の摩擦になる」とある。正準形（書き換えの `canonical form:`）と関連位置（アンカー）は R46〜R52 で入った。残るのは型の印字である。

### 実測した材料

`cargo run --offline -q -- check <file>` の本文（2026-09-16 実測）。

| 形 | いまの本文 |
|---|---|
| `def add1 (x: Int): Int Pure => x + 1` に `add1 "hi"` | `error[E305]: cannot unify Fn(Int => Int) with Fn(String => t900)`（位置は実引数 `"hi"`） |
| `if 1 > 2 => 1 \| "x"` | `error[E305]: cannot unify String with Int` |
| `[1, true]` | `error[E305]: cannot unify Bool with t898` |
| `def twice f x => f (f x)` に `twice (fn(y => y + 1)) true` | `error[E305]: cannot unify Fn(Fn(t906 => t906), t906 => t906) with Fn(Fn(t909 => Int), Bool => t910)` |
| `def self_apply f => f f` に `self_apply 0` | `error[E306]: cannot unify t898 with Fn(t898 => t899)` |
| `def apply2 (f: Fn(Int => Int)): Int Pure => f 1` に `apply2 fn(x => x > 0)` | `error[E305]: cannot unify Fn(Fn(Int => Int) => Int) with Fn(Fn(t904 => Bool) => t905)` |

分かったこと 3 つ。(1) 型変数が内部の番号（`t900`）で出るので読めず、番号は実装の都合で変わる。(2) 適用の引数で食い違ったとき、アンカーは正しく**実引数**を指すのに、本文は**関数型どうし**（`Fn(Int => Int)` と `Fn(String => t900)`）を出している。利用者が知りたいのはその引数の型と仮引数の型である。(3) 引数以外の食い違いは 2 つの型の順序が揃っていない（`if` の腕は実型が先、注釈は期待型が先）。

実装は既に材料を持っている。`apply` は `application_argument_span` の中で推論を clone して探針し、**どの引数で食い違ったか**を求めている。そこでは仮引数型と実引数型の対も手に入る。

### 決定

- **決定 1: E305 の本文を 2 形にする。** 適用の引数の食い違いは `expected <仮引数の型>, found <実引数の型>`（役割が確定しているので名指しする）。それ以外の食い違いは `cannot unify <a> with <b>` のまま（順序に意味があるとは限らないので対称な言い方にする）。E100 の `expected <トークン>, found <トークン>` と同じ語順にする。
- **決定 2: E306 は `cannot unify <a> with <b>` のまま。** 出現検査は「2 つの型が食い違う」話ではなく、`wants.md` の 3 も E305 を名指ししている。
- **決定 3: 診断に出る型の変数は §58.3 と同じ改名をする。** `A` `B` … `Z` `A1` … と現れる順。内部の番号は印字しない。**1 つの診断では 1 つの対応表**を使うので、両方の型に現れる変数は同じ名前になる（`cannot unify A with Fn(A => B)`）。
- **決定 4: 対は既存の探針から取る。** `application_argument_span` を `application_mismatch` に広げ、`(位置, Option<(仮引数型, 実引数型)>)` を返す。探針は clone なので、**型は単一化を試す前に解決してから**対にする（失敗した単一化の途中経過を印字しない）。
- **決定 5: 仕様は §15 の直後に `## 15.1. 型の食い違いの印字`。** §58.3 と互いに参照する。
- **決定 6: `Ty` 自身の印字は変えない。** `--print-type` の `main` と値なしの形は §58 のまま。§15.1 と §58.3 は同じ改名規則を使うが、行の扱い（§58.3 は開いた行の変数を `| A` で出す）は §58.3 の規則である。
- **決定 7: 文言の変更で赤になる既存の門番は意図を保って直す。** `verify-r33.sh` の 33-f2 と 33dist はどちらも「E305 が両側の型を名指しする」ことを測っている。文言を直し、意図（両側が出る、`.T` が出ない、A と B が混ざらない）はそのまま測る。過去のラウンドの計画・台帳の実測表は当時の語のまま残す。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| `add1 "hi"` | `expected Int, found String`、位置は実引数の先頭 | 決定 1、決定 4 |
| `twice (fn(y => y + 1)) true` | `expected A, found Bool` | 決定 1、決定 3（仮引数の型変数が `A`） |
| `apply2 fn(x => x > 0)` | `expected Fn(Int => Int), found Fn(A => Bool)` | 決定 1、決定 3 |
| `self_apply` の `f f` | `cannot unify A with Fn(A => B)`（E306） | 決定 2、決定 3（共有する変数が同じ名前） |
| `[1, true]` | `cannot unify Bool with A`（E305、引数以外） | 決定 1、決定 3 |
| `if 1 > 2 => 1 \| "x"` | `cannot unify String with Int` | 決定 1（引数以外） |

### 判定

`scripts/verify-r56.sh` を新設し、55 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で仕様の形から書く。** control を先に回す。

- 判定 56-a: 適用の引数の食い違いが `expected <仮引数型>, found <実引数型>` で、アンカーは実引数の先頭（`add1 "hi"`）。
- 判定 56-b: 仮引数の型が型変数のときの対（`twice (fn(y => y + 1)) true` が `expected A, found Bool`）。
- 判定 56-c: 出現検査は `cannot unify` のまま（`self_apply` が `cannot unify A with Fn(A => B)`）で、両側に現れる変数が同じ名前である。
- 判定 56-d: 引数以外の食い違いは `cannot unify`（`[1, true]` が `cannot unify Bool with A`、`if` の腕が `cannot unify String with Int`）。
- 判定 56-e: 生成した複数の形のどれも本文に `t<数字>` を含まない（改名の不変条件）。
- 判定 56-f: 文書（§15.1 と追跡表と wants）・層の `r56`・corpus lock。

### 許容される赤

工程 1 の直後は 56-a〜56-e が赤でよい（`t<数字>` が残る）。33-f2 と 33dist も `cannot unify` を期待しているので赤になる（工程 3 で意図を保って直す）。**R56 の終了時に許容される赤は無い。**

### スコープ外

- 引数以外の食い違いの役割（期待型/実型）の明示。順序が揃っていないので、まず適用の引数だけにする
- 関連位置（E205 や E602 が 2 か所を指す形、`--print-type` の値なしの形の併記）
- E507 / E508 の書き換え、レイアウトの正規化（`wants.md` の 11）
- `mono.rs` の内部エラー（`specialization failed: ...`）の印字。あれは不具合の報告であって利用者の型の誤りではない

### 確認して報告（決定から）

- `--print-type`（値なしの形）と `--print-type=<名前>` の出力が 1 バイトも変わっていないこと（決定 6）
- 同じ変数が 1 つの診断の中で 2 つの名前にならないこと（決定 3）
- 33-f2 と 33dist が文言の変更の後も「両側の型を名指しする」ことを測っていること（決定 7）
