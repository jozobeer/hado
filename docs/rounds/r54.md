# R54 `hado test` を入れる手順書（2026-09-16）（r54）
旧 `docs/plan.md` 50 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`wants.md` の 40（中）が「`hado test`。R20 の複数入口を順に `run` する。`*_test.hd`。assert マクロは足さない（§4）。10 の後」と、`hado run`（R48）の後に置いていた。R20 が複数入口を入れたので、入口ファイルを複数持つプロジェクトは既に書ける。足りないのは「どれがテストかを決めて、順に走らせて、結果をまとめる」部分だけである。

`hado run` は既にビルドと実行と終了コードを持つ（§58）。§54 のとおり、`main` まで届いた `raise` は `Exception` の `message` を stderr に印字して終了コード 1、正常終了は 0 である。したがって**テストの合否は終了コードで足りる**。新しい言語意味は 1 つも要らない。

### 実測した材料

| 形 | `hado run` |
|---|---|
| `def main = check 1`（`check` が `Void {Error}` を返し、合格） | 何も印字せず終了 0 |
| `def main = raise { message = "boom" }`（不合格） | stderr に `boom`、終了 1 |
| `def main = 1 + true`（ビルドが通らない） | stderr に E305、終了 1 |
| 下位ディレクトリの `module` を使うテスト（`library` と `implement`） | 期待どおり 0 / 1（§50 の参照の綴りで書ける） |

`main` の値が `Void` のときは何も印字されない（§55）。`tests/accept/abort_effect/main.hd` が `def main = raise { message = "stopped" }` で、`main` が `{Error}` を持てることを既に固定している。

### 決定

- **決定 1: `hado test <file.hd>` を足す。** 入力根（§50）の直下にある `*_test.hd` を、§50 の順序（相対パスのバイト順）で順に `run` する。
- **決定 2: 合否は終了コード。** 0 が合格、0 以外が不合格。`raise` が `main` まで届いた場合も、スタックが尽きた場合も、シグナルで終わった場合も不合格である。**新しい言語意味と診断コードを足さない。** assert マクロも足さない（§4、`wants.md` 40）。テストは `if 条件 => () | raise { message = "..." }` を書く。
- **決定 3: 選ぶのは根の直下だけ。** `main` を持てるのは根のファイルだけなので（§50、§52）、テストも根の直下に限る。下位ディレクトリの `*_test.hd` は選ばない。
- **決定 4: 順に走らせ、1 本が落ちても残りを走らせる。** 1 本ごとに `test: <相対パス> ok`、`test: <相対パス> failed (exit <n>)`、`test: <相対パス> failed (signal)`、`test: <相対パス> failed (build)` のどれかを標準出力に出す。ビルドの診断は標準エラーに出す。
- **決定 5: まとめの行を出す。** `test: <合格>/<全部> passed` を標準出力に出す。全部合格なら終了 0、1 本でも落ちれば終了 1。
- **決定 6: テストが 1 本も無ければ終了 1。** `test: no *_test.hd in the input root` を標準エラーに出す。名前の綴り違い（`main_tests.hd`）が静かに通らないようにする（迷ったら拒否、`docs/rounds/r6.md`）。
- **決定 7: 標準入力・標準出力・標準エラーはテストにそのまま渡す。** `run` と同じである（`wants.md` の「順に `run` する」）。テスト自身の出力はそのまま見える。捕捉して落ちたときだけ見せる形は R54 では採らない。
- **決定 8: テストに引数を渡さない。** `--` の後の引数は `run` だけのものである。`test` に `--` を書くと usage（終了 2）。
- **決定 9: 既定の `check` / `build` / `fmt` はテストを特別扱いしない。** `main_test.hd` も普通のソースとして検査と整形の対象になる（§50、§58.1）。テストが型の誤りを持てば `check` も落ちる。
- **決定 10: 仕様は `## 58.2. テストの実行` を §58.1 の直後に足す。** 追跡表に 1 行足す。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| 合格する `*_test.hd` 3 本 | 3 本とも `ok`、`3/3 passed`、終了 0 | 決定 1、決定 5 |
| `raise` する 1 本を含む 3 本 | `failed (exit 1)` が 1 本、`ok` が 2 本、`2/3 passed`、終了 1、3 本とも走る | 決定 2、決定 4 |
| 型の誤りを持つ 1 本 | `failed (build)`、診断は標準エラー、残りは走る | 決定 4 |
| `main` を持たない `*_test.hd` | `failed (build)`（E206） | §52、決定 4 |
| `*_test.hd` が無い根 | 標準エラーに `no *_test.hd`、終了 1 | 決定 6 |
| 下位ディレクトリの `*_test.hd` | 選ばない | 決定 3 |
| テストの標準出力 | そのまま出る | 決定 7 |

### 判定

`scripts/verify-r54.sh` を新設し、53 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** control を先に回す。

- 判定 54-a: 合格するテスト 3 本が相対パスのバイト順で走り、1 本ごとの行と `3/3 passed` が出て終了 0。テストが stdout に書いた値がそのまま出る。
- 判定 54-b: `raise` するテストを間に置くと、その 1 本だけが `failed (exit 1)` で、前後が `ok`、まとめが `2/3 passed`、終了 1。落ちた後のテストの出力が出る（残りも走る）。
- 判定 54-c: 型の誤りを持つテストは `failed (build)`、`main` を持たないテストも `failed (build)`。診断は標準エラーに出て、他のテストは走る。
- 判定 54-d: `*_test.hd` が無い根では標準エラーに `no *_test.hd`、終了 1。`mytest.hd` と `main_tests.hd` はテストではない（control）。
- 判定 54-e: 下位ディレクトリの `*_test.hd` は選ばれない（根の直下のものは選ばれる control つき）。
- 判定 54-f: 文書（§58.2 と追跡表と wants）・層の `r54`・corpus lock。
