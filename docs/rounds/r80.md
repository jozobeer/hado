# R80: パイプラインを関数適用結果から始める（2026-09-17）（r80）
旧 `docs/plan.md` 75 節。実測は `docs/ledger.md`。

## 手順書

### 背景
R79 は `value |> f |> g` を連続適用として残したが、値からパイプを書き始めると、最初の一段までパイプラインの都合に合わせて読む必要がある。最初の適用は `f value` と書き、その結果を次の関数へ渡す地点からパイプラインにする。

### 決定
- `value |> f |> g` は `f value |> g` と書く。さらに変換が続く場合は `f value |> g |> h` とする。
- 最大のパイプ式の左端は、並置による関数適用でなければならない。
- `x |> f` と `f x` が同義である言語仕様は変えない。§14 の推奨例と配布コードの書き方を変える。
- 配布対象は R79 と同じ `stdlib/`、`tools/`、付録Bの典型コードと対応する受理ケースとする。
- 回帰検査は最大のパイプ式の左端を構文木から調べ、値から始まるパイプラインを列挙する。

### 成果物
- `docs/spec.md` §14・付録B、配布対象の `.hd` / `.hdi`。
- 値から始まるパイプラインを検査する Rust の統合テスト。
- `tests/corpus.sha256` と `docs/ledger.md`。

### 工程
1. この手順書をコミットする（`docs:`）。
2. 最大のパイプ式の左端を検査し、現状で赤を測る（`test:`）。
3. 最初の関数適用だけを直接適用へ変え、対象の既存テストで確かめる（`refactor:`）。
4. corpus lock を更新し、quick、`cargo test`、台帳を一回ずつ走らせて閉じる（`docs:`）。

### 判定
- 80-a 配布対象の最大パイプ式がすべて直接の関数適用結果から始まる。
- 80-b 二つ目以降の関数適用はパイプラインのまま残る。
- 80-c §14 と付録Bの例が同じ書き方を示す。
- 80-d 受理・ライブラリコーパスと二つの配布ツールの既存の判定が変わらない。
- 80-e corpus lock、quick、`cargo test` が緑である。

### 中断の条件
- 最初の適用を直接適用へ変えることで型、効果、評価順のいずれかが変わるとき。
- 最大のパイプ式の左端を構文木から一意に判定できないとき。
