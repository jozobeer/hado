# R63 Boolean 分岐の正準形への書き換え（2026-09-16）（r63）
旧 `docs/plan.md` 59 節。実測は `docs/ledger.md`。

## 手順書

### 背景

R62（58 節）は E503 だけを入れ、E520 の書き換えを落とした。理由は `crates/hado/src/fixes.rs` が式の範囲を `branch_range` で取るのに、これが `ast.branch_spans` に載っている枝の位置でしか働かないことで、E520 の形は引数や `let` の値にも現れるためだった。

しかし §24 の 2 つの形（`if b | true => x | false => y` と `if b | true => x | y`）のうち、定義の本体にあるものは枝の位置であり、`branch_range` が使える。診断のアンカー（`if` の位置）は `node.span` と一致する。R63 はこの位置に限って書き換えを入れる。

### 実測した材料

`crates/hado/src/check.rs` の `check_boolean_form`（304 行から 322 行）が E520 の条件である。`PatternBranch` で scrutinee が 1 つ、腕が空でなく、すべての腕の pattern が Bool リテラル 1 つ（`PatternKind::Literal` で中の `NodeKind::Bool`）のとき。`CondBranch` で腕が 1 本のときも E520（これは条件が腕ではないので今回は入れない）。診断の位置は `node.span`。

R62 の実測（58 節の表）から、`if b | true => 1 | false => 2` は `1:25`、`if b | true => 1 | 2` も `1:25` で E520。`Some(true)` と 2 条件列は除外。`def f (b: Bool): Int => if | b => 1 | 2` は E517 が先に当たる。

### 決定

1. `PatternBranch` で scrutinee が 1 つ、すべての腕の pattern が Bool リテラル 1 つ、かつ（腕が 2 本で fallback 無し）または（腕が 1 本で fallback 有り）のとき、`if <scrutinee> => <true の腕> | <false の腕>` にする。腕の順は真偽で選ぶので、書かれた順が逆でも値は変わらない。
2. 範囲は `branch_range(node, Tail::If, source, lines, tokens, index, branches)`。枝の位置でない E520（引数や `let` の値）は書き換えを出さない。診断はそのまま出る。
3. 腕が 2 本で fallback もある形は書き換えない。Bool の分岐は 2 本なので正準形が無い。
4. 腕が 1 本だけの条件列（`CondBranch` で腕 1 本）は R62 のスコープ外を維持する。条件の位置が腕ではないので同じ書き換えでは表せない。
5. 書き換える範囲に `//` を含めない（§57）。診断の本文は変えず、既存の `hint` の仕掛けで `canonical form` を出す。

### 期待値の根拠

| 入力 | 期待 | 根拠 |
|---|---|---|
| `if b \| true => 1 \| false => 2` | `if b => 1 \| 2` | §24 の canonical form |
| `if b \| true => 1 \| 2` | `if b => 1 \| 2` | 同上 |
| 引数の位置の `if b \| true => 1 \| false => 2` | 書き換えない（診断だけ） | 枝の位置でない |

### 追記（実装中に分かったこと）

`branch_range(Tail::If)` は枝の位置だけでなく、引数の位置と `let` の値の位置でも効いた（実測）。決定 2 の「枝の位置に限る」は実装では制限にならず、測ったすべての位置で書き換えが出る。R62 の台帳に「E520 の形は引数や `let` の値にも現れ、その場合は式の終わりの位置が AST に無いので範囲を作れない」と書いたが、これは `branch_range` と `branch_entry` を読んで判断した誤りで、測れば効く。門番 63-d は引数の位置と `let` の値の位置が書き換わることを測る形に変えた。
