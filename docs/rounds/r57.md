## 手順書

### 背景

`wants.md` の 1（高）「冗長の診断に正準形を出す」と 11（高、`hado fmt`）の残り。R46〜R52 で `check --fix` / `fmt` / `build --fix` の仕組みと E510 / E516 / E517 / E515 / E501 の書き換えを入れた。§57 の一覧に残っていたのは E507 と E508 である。どちらも §45 / §36 に正準形が書かれているのに、書き換えを出していなかった。

### 実測した材料

- `tests/reject/E507/main.hd`（第31節の形）は `main.hd:1:1: error[E507]: branches reconstruct the value at 1:1` を出し、`canonical form:` を出さない。`tests/reject/E508/main.hd` は `main.hd:7:3: error[E508]: absence bound at 7:5 is propagated unchanged; use let p? = or do` を出す（アンカーは `|`。`arm_diagnostic` が `branch_anchors` で腕の `|` に寄せている）。
- 検査は `check_rewrap`（E507）と `check_repropagation`（E508）にある。E507 は「すべての腕が自分の pattern を組み直し、fallback は scrutinee と同じ」、E508 は「`None` の腕の本体が `None` の組み直し」を見る。腕が `| Some(v) => Some(v) | None => None` の分岐は**両方**に当たる。
- 分岐の形は 3 つある。`if E | ...`（ノードの位置は `if`）と、第31節の `def f | ...` と `fn(| ...)`（どちらも `parse_arm_function` が引数 `$argument` と pattern 分岐 1 つに落とし、ノードの位置は `def` / `fn`）。
- **E508 の書き換えは位置を選ぶ。** 本体でない `if` を素直に `let p? =` へ直すと型が通らない。実測: `let y = if find_user id | Some(user) => Some(user + 1) | None => None -> ...` は E508 だけを出すが、これを `let user? = find_user id -> Some(user + 1)` にすると `error[E305]: cannot unify Int Option with R` になる。`let p? =` の伝播先は囲む関数なので、分岐が関数の**本体ちょうど**でないと伝播の意味が変わる。
- `fn` の中の `let p? =` はその `fn` を伝播先にする（実測: `fn(y => let v? = y -> Some(v + 1))` は `Fn(Int Option => Int Option)` になる）。
- `let p? =` の `p` は `Option` の**中の**値の pattern である（§36 の例: `| Some(user) => ...` → `let user? = ...`）。`let` に置ける pattern は q1〜q4 の探針で確かめた: `Some(Some(v))`・`P(a, b)`・record は通り、リテラルは E402（binding pattern does not cover its type）になる。
- `parser::canonical` は式を 1 行に印字する（`1 + 2 * 3` は `(1 + (2 * 3))`、名前とリテラルは裸）。`Display for Pattern` は pattern を印字し、`parser::list_pattern` が `Nil` / `Cons` の正準形を出す。
- `scripts/verify-r46.sh` の 46-e は「直せない診断」の例に E507 を使っている。R57 で E507 が直せるようになる。

### 決定

- **決定 1: §57 の一覧に E507 と E508 を足す。** 条件は検査と同じ形に、位置と使い方の条件を足す。
- **決定 2: E507 の正準形は scrutinee そのもの。** 第31節の形は `def f value => value`、`fn` は `fn(value => value)`（腕がすべて scrutinee の組み直しなので、引数の名前は `value` でよい）。`if` の形は `parser::canonical(scrutinee)` を書く（名前とリテラルは裸、複合式は括弧付きなので、どの位置に置いても綴りが変わらない）。**fallback を持つ形には書き換えを出さない**（fallback は scrutinee の再評価であり、1 回に畳むと効果の回数が変わり得る）。
- **決定 3: E508 の正準形は `let <内側の pattern>? = <scrutinee> -> <本体>`。** 書き換えを出すのは次をすべて満たすときだけ。(1) 分岐が `def` か `fn` の本体ちょうど（第31節の形は常にそう）、(2) 腕が 2 本で fallback なし、(3) 2 本目が `None` の腕でその本体が再伝播、(4) 1 本目の pattern が `Some` 1 引数、(5) その内側の束縛名がすべて本体で使われている（1 つも無い形と、使われない形は `do` が正準形なので出さない）、(6) 分岐が E507 の形（すべての腕が組み直し）ではない。本体でない位置では伝播先が違うので出さない（実測）。
- **決定 4: 置換のテキストはソースの綴りを写す。** 範囲の端は字句から取り、直後の字句の手前まで空白を戻す。`fn(| ...)` の形だけは範囲の終わりを対応する `)` の次までにする（分岐の直後の字句はその `)` で、置換が `fn(...)` を丸ごと書くためである。実測で分かった）。診断に出す `canonical form:` は改行を空白に畳んだ 1 行（`canonical` は 1 行を要求する。範囲に `//` を含まないことは書き換えの条件なので、畳んでも comment を呑まない）。
- **決定 5: 分岐の範囲は `Ast` の新しい表から取る。** `branch_spans: Vec<(Span, Span, Span)>` = 分岐の開始・最初の `|`・分岐の直後の字句。`fixes` は分岐の開始位置で引く。既存の `branch_anchors` と同じ扱いにする（`isolate` では触らない。prelude の合成と functor の行ずらしでは同じように足す）。
- **決定 6: E508 のアンカーは `None` の腕の `|`。** 検査が `branch_anchors` で寄せている位置と同じにするため、pattern の位置から `branch_anchors` を引く。
- **決定 7: `verify-r46.sh` の 46-e の例を E505 に差し替える。** 未使用は直さないと決めている（`wants.md`）。E507 が直せるようになったので、例と文言を直す。

### 判定

`scripts/verify-r57.sh` を新設し、56 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で仕様の形から書く。** control を先に回す。

- 判定 57-a: E507 の `if` 形。生成した Option 値で、`check` が `canonical form: <scrutinee>` を出し、`check --fix` の後の本文が scrutinee の綴りになり、`build` と実行の出力が scrutinee の値と一致する。
- 判定 57-b: E507 の `def` / `fn` の形。正準形が `def f value => value` / `fn(value => value)` で、直したプログラムの実行値が入力と一致する。

- 判定 57-d: E508 の `def` / `fn` の形。`def f value => let ...` へ直り、実行値が一致する。
- 判定 57-e: 負の対照。本体でない E508、fallback を持つ E507、束縛名が本体で使われない E508、コメントを含む E507 のどれも `canonical form:` を出さず、`fmt` がファイルを変えない。
