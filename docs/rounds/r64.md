# R64 fmt のレイアウトの正規化（2026-09-16）（r64）
旧 `docs/plan.md` 60 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/wants.md` の 11（高）の残り「レイアウトの正規化」。§58.1 の `fmt` は §57 の局所的な書き換えだけを当て、字下げや行末には触れない。

### 実測した材料

`def main =
\t1   `（タブの字下げ、行末の空白 3 つ、末尾の改行なし）を書いて測った。

```
$ hado fmt --check main.hd   → check=0
$ hado fmt main.hd           → fmt=0（何も書かない。cat -A は `def main =$` と `^I1   ` のまま）
$ hado check main.hd         → check=0
```

つまりこの形は `fmt --check` を通り、レイアウトは正規化されていない。全走は R63 の `TALLY: 3666/3666 passed; red: none`。

### 決定

1. `fmt`（§58.1 の一括整形）は、局所的な書き換えに加えて、行末の空白（スペースとタブ）を消し、ファイルの終わりを改行 1 つにする。空のファイルはそのまま。
2. 書き換えを当てた後に当てる。書き換えが持ち込む行末を整えるためである。
3. `check --fix` は診断のアンカーに一致する書き換えだけを当てるので、レイアウトは当てない（§57 のまま）。
4. 数える数は書き換えとレイアウトの変更の合計とし、`fmt: <相対パス> (<n> rewrites)` の綴りは変えない。
5. 字下げの幅（タブをスペースに直すか）と改行コード（CRLF）と空行の数は決めない。スコープ外。

### 期待値の根拠

| 入力 | `fmt` の後 | 数 |
|---|---|---|
| `def main =
\t1   ` | `def main =
\t1
` | 2（行末の空白 1、末尾の改行 1） |
| `def main =
  1
` | 変わらない | 0 |
| 空のファイル | 変わらない | 0 |

### 判定

- 64-a タブ字下げ + 行末の空白 + 末尾の改行なしのファイルが、`fmt` で行末の空白が消え末尾に改行が 1 つ付き、字下げのタブは残る。数は 2。`fmt --check` は直す前 1、直した後 0。
- 64-b 正準なファイルは変わらない（`fmt` は何も出さず終了コード 0、`fmt --check` も 0）。
- 64-c 空のファイルは変わらない。
- 64-d `check --fix` はレイアウトを当てない（診断が無ければ何も書かない）。
- 64-e 文書と層、64-f corpus lock。

### 許容される赤

- 実装前の 64-a。64-b〜64-f は緑のはずである。

### スコープ外

- 字下げの幅、CRLF、空行の数、全 AST の再印字（コメントを失う危険がある）。
- E502 / E504 / E506 / E511 / E512、`hado explain`、`--format json`。

### 確認して報告

- 行末の空白を持つ既存のソースが `fmt` の対象に入るか（入力根の全部が対象である §58.1 のため）。
- 数の意味が「書き換え」から「変更」に広がることの綴りへの影響。
- タブの字下げを残す判断（幅を決めるとソースの見た目を勝手に変えるため）。

### 中断の条件

- 正準なファイルの数が 0 にならない既存の門番が出たとき。
- 行末の空白を消すことで、`//` の後ろのコメントの意味が変わるとき（無いはずである）。
