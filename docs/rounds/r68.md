# R68 E512 の書き換えの手順書（2026-09-16）（r68）
旧 `docs/plan.md` 63 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/wants.md` の 1（高）の残り。E512（`top-level variable patterns are forbidden`、§26）は、R62 の E503（catch-all の `_` を fallback に）と同じ形の冗長だが、書き換えの対象になっていない。R63 までの実測で、正準形は fallback では終わらないことが分かっている。

補足（R67 の追測）: 受理コーパスを走らせる門番 `scripts/verify-r67.sh` は、以前は実行を作業ディレクトリ（リポジトリの根）で行っていたためファイル I/O の受理ファイルが根に `fixture` / `ordinary` を書いていた。これを一時ディレクトリに直し、全走は `3680/3680 passed; red: none` を exit 0 で終える（R67 の台帳）。E512 の門番も同じ隔離で実行の判定をする。

### 実測した材料

- 再現: `type T = | A | B` と `def f (t: T): T => if t | A => A | y => y` と `def main = f A` で `main.hd:2:36: error[E512]`。
- `check.rs` の `catch_all_row`（436 行）: 腕の pattern がすべて `_` か変数で、どれかが変数のとき E512。すべて `_` なら E503。
- E512 の fallback 形（`| t`）は **E507**（`branches reconstruct the value`）を出し、`hado fmt` は書き換えない（R57 の E507 の書き換えは fallback のある形を避ける。実測）。
- R62 の E503 の書き換えは `fixes.rs` の `catch_all_fallback_fix`。範囲は `branch_range` / `branch_entry`（R63 で `Tail::If` と `Tail::Fn`、枝の位置に限らないと実測）。

### 決定

1. `fixes.rs` に E512 の書き換えを足す。腕が 1 本で、その腕の pattern がすべて `_` か変数、どれかが変数、scrutinee が**単純な変数**（`NodeKind::Name`）のときだけ対象にする。
2. 書き換えは、腕を fallback にし、本体に現れる束縛を **scrutinee の名前に置き換える**。置き換えは重ならない複数の編集でよい（`fixes` は複数の編集を持てる）。範囲に `//` を含むときは書かない（R62 の `push_edit` と同じ規則）。
3. 生成した形が **E507 を出すなら、条件ごと scrutinee に畳む**（`if t | A => A | y => y` を `t` に）。ここは測ってから決める。単純な fallback で止めると、直したファイルが別の冗長で落ちる。
4. `fmt` と `check --fix` の両方から同じ書き換えを使う（§57 / §58.1 の共有。R62 以降と同じ）。

### 期待値の根拠

| 入力 | 期待 |
|---|---|
| `if t | A => A | y => y` | 受理される形（`t` か、E507 を出さない形）に書き換わり、`check` が 0 |
| `if t | A => A | y => 0` | 束縛を使わないので、fallback の `| 0` で足りる（E505 が先に出る場合は対象外） |
| 束縛を使い、scrutinee が単純な変数でない（例: 関数呼び出し） | 書き換えない（正準形を示すだけ） |
| 範囲にコメントがある | 書き換えない |

### 判定

- 68-a E512 の再現で `check --fix` が終了コード 0、直したファイルが `check` を終了コード 0 で通る。
- 68-b `hado fmt` も同じ結果を出し、2 回目は何も変えない（冪等）。
- 68-c 束縛を scrutinee に置き換えても値が変わらない（R67 の門番と同じ隔離で実行して比べる）。
- 68-d 対象外の 4 つの形（束縛を使わない / scrutinee が単純でない / コメントがある / 腕が複数）では書き換えない。
- 68-e 仕様、追跡表、層、corpus lock。

### 許容される赤

- 工程 2 の 68-a / 68-b。68-d / 68-e は緑のはずである。

### スコープ外

- 残る 4 つの冗長（E502 / E504 / E506 / E511）、E305 の関連位置、終了コード（wants 25）。
- `tools/gates/main.hd` への `--format json` の導入。R67 の追測で、この道具は門番のログの `PASSED:` の行を集計するもので、診断を読む道具ではないと分かった（`scripts/verify-r51.sh:34` が `hado run tools/gates/main.hd -- <ディレクトリ>` で走らせる）。JSON を食う道具は別に作る。

### 確認して報告

- 置き換えた名前が本体で **影** になっていないか（内側の `let` が同じ名前を使う場合）。影があれば置き換えず、正準形を示すだけにする。
- E512 と E503 が同時に出る形があるか（R62 の E503 と重ならないか）。

### 中断の条件

- 生成した形が E507 を出し、条件ごと畳むと本体の効果の順序が変わり得るとき。
- 影の判定が構文だけでは決まらないとき。
