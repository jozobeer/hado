# R79: パイプラインを連続適用に限定する（2026-09-17）（r79）
旧 `docs/plan.md` 74 節。実測は `docs/ledger.md`。

## 手順書

### 背景
R78 は直接適用を広くパイプラインへ変えたため、`value |> f` のように変換が一段しかない箇所までパイプラインになった。パイプラインは、関数の結果へさらに関数を適用する流れを左から右へ読むために使う。

### 決定
- 最大のパイプ式に `|>` が二つ以上ある連続適用だけをパイプラインで書く。
- `value |> f args` のような一段のパイプ式は `f value args` の直接適用へ戻す。
- `value |> f |> g` のような連続適用は維持する。型、評価順、効果、期待出力は変えない。
- 配布対象は R78 と同じ `stdlib/`、`tools/`、付録Bの典型コードと対応する受理ケースとする。
- 回帰検査は直接適用を禁止せず、最大のパイプ式が一段だけの箇所を構文木から列挙する。

### 成果物
- 配布対象の `.hd` / `.hdi` と `docs/spec.md` 付録B。
- 単段パイプを検査する Rust の統合テスト。
- `tests/corpus.sha256` と `docs/ledger.md`。

### 工程
1. この手順書をコミットする（`docs:`）。
2. 最大の単段パイプを列挙する検査へ変更し、現状で赤を測る（`test:`）。
3. 一段のパイプ式だけを直接適用へ戻し、対象の `check` または既存テストで確かめる（`refactor:`）。
4. corpus lock を更新し、quick、`cargo test`、台帳を一回ずつ走らせて閉じる（`docs:`）。

### 判定
- 79-a 配布対象に最大の単段パイプ式が残らない。
- 79-b 最大のパイプ式が二段以上の箇所はパイプラインのまま残る。
- 79-c `stdlib/` の各ファイルが `hado check` を通る。
- 79-d 受理・ライブラリコーパスと二つの配布ツールの既存の判定が変わらない。
- 79-e corpus lock、quick、`cargo test` が緑である。

### 中断の条件
- 直接適用へ戻すことで型、効果、評価順のいずれかが変わるとき。
- 最大のパイプ式の段数を構文木から一意に判定できないとき。
