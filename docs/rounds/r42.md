# R42 節番号を増やしても動かない形にする手順書（2026-09-15）（r42）
旧 `docs/plan.md` 38 節。実測は `docs/ledger.md`。

## 手順書

### 背景

本文と付録を 1 本の通し番号で振り、`§N` を corpus の `// spec:`・エラー表の節欄・門番・コードのコメントが読む識別子にしてきた。この形では本文の途中に 1 節増えるだけで、それ以降の番号を全部ずらすことになる（R39・R40 で 2 回行った）。仕様書を今後も保守することを考え、番号を増やしても既存の参照が動かない形にする。

### 決定

1. **付録は本文の番号系列から外す。** `## 付録A コア構文`・`## 付録B 典型コード`・`## 付録C 文法の概形` とし、機械参照も `付録A` の形にする。
2. **本文の新しい節は小数番号で入れる。** 既存の整数番号は動かさない。直前の節の直後に `§20.1` のように足す（読み順は 20 → 20.1 → 21）。新しい整数は本文の末尾にだけ足す。
3. **表示番号と機械参照は同じ表記を使う。** corpus の `// spec:`・エラー表の節欄・門番・コメントは、本文 `§N`（将来は `§N.M`）と付録 `付録X` をそのまま使う。
4. **本文 §1〜§56 の番号と内容は変えない。** 付録の文字と、付録を引く参照だけを変える。

### 手順

1. `docs/spec.md` の付録 3 節の見出しを `付録A/B/C` にし、目次と、付録を引く本文（E100 の節欄と説明）を追随させる。
2. 付録を引く参照を追随させる（`docs/spec-trace.md`・`docs/spec-coverage.md`・`docs/corpus.md`・`docs/wants.md`、`crates/` のコメント、Rust テスト）。
3. corpus の `// spec: §58` 11 件を `付録B`、`§59` 1 件を `付録C` にし、`tests/corpus.sha256` を更新する。
4. 門番を追随させる。`lint-docs.sh` は本文の整数と付録の文字を分けて検査する。`verify-m1-corpus.sh` は典型コードの節見出しとタグを `付録B` にする。`verify-m2.sh` と `verify-r23.sh` のタグとラベル。`verify-r41.sh` を `verify-r42.sh` にし、節の並びと corpus のタグ・エラー表の節欄が `§N` と `付録X` を取る形にする。`scripts/lib/gate-tiers.sh` の full の `r41` を `r42` にする。
5. 保守の規約を `AGENTS.md` と `docs/corpus.md` に書く。
6. `docs/ledger.md` に R42 を書く。
7. `scripts/run-gates.sh` の quick・core・full と `cargo test --offline --no-fail-fast` を回す。
8. tag `v0.3.1` を最終コミットに付け直す。

- 42-b. `scripts/lint-docs.sh` が満点。
- 42-c. `scripts/verify-gate-cache.sh` が満点。
- 42-d. `scripts/run-gates.sh --tier quick`・`--tier core`・`--tier full` が exit 0 で、`^NG:` が 0。
