# R48 `hado run` と安全な出力先の手順書（2026-09-16）（r48）
旧 `docs/plan.md` 44 節。実測は `docs/ledger.md`。

## 手順書

### 背景

R46・R47 で「書いて、直す」は一巡した。次は「実行する」である。CLI は `check` / `dump-mono` / `build` だけを持ち、`build` は入力の隣に実行ファイルを書く（`crates/hado/src/main.rs:48`）。書き込みできない根、読み取り専用の根、入力の隣を汚したくない場面では使えない。

言語側には既に実行の材料がある。`log` は標準出力へ行を書き（`stdlib/io.hd:25`）、`args` はプログラム名を除く引数を返し（§55）、`read_stdin` は標準入力を読む。失敗は `raise` で伝わり、既定実装が標準エラーへ `message` を書いて終了コード 1 を返す（実測）。

足りないのは CLI の縦切りである。`run` は一時ディレクトリへ作り、標準入力・標準出力・標準エラーをそのまま渡し、子プロセスの終了コードを返す。`build` には出力先を明示する `-o` を足す。これで「入力の隣を汚さない実行」ができる。

### 決定

- **決定 1: `hado run <file.hd> [-- <arg>...]` を足す。** `--` の後だけが子プロセスの引数である。`--` が無ければ引数は無い。`--` の前の引数は入力ファイル 1 つだけで、他の旗は受け付けない（`--flag` は入力ではなく使用法の誤り）。
- **決定 2: `run` は一時ディレクトリで作って消す。** `std::env::temp_dir()` の下に `hado-run-<pid>-<連番>` を作り、そこへ `program` をリンクして実行し、終了後にディレクトリごと消す。入力の隣には何も置かない。連番は既存のディレクトリと衝突したら進める。
- **決定 3: `run` は標準入出力と現在の作業ディレクトリを変えない。** `Command::status` の既定（継承）を使い、`current_dir` を設定しない。`args` はプログラム名を含まないので、子プロセスの argv[0] が一時パスでも `Env.args` の見え方は変わらない。
- **決定 4: `run` の終了コードは子プロセスの終了コード。** 子プロセスがシグナルで終わり終了コードが無いときは、`run` の終了コードを 1 とし `run: the program was terminated by a signal` を標準エラーに出す。
- **決定 5: `build` に `-o <path>`（`--output` も同じ）を足す。** 既定の出力先は今まで通り入力の拡張子を除いた隣にする。門番と既存の利用を変えない。
- **決定 6: `build` と `run` の失敗も `check` と同じ `report` を通す。** 診断に局所的な書き換えがあるときは `canonical form:` を付ける。今は `compile_to_object` が `error.to_string()` に落としていたので、`build` だけ正準形が出ていなかった。
- **決定 7: 仕様は §58 を本文の末尾（§57 の後）に足す。** 命令の綴り、出力先、終了コード、引数の渡り方を書く。整数の節を本文の末尾に足す規則（AGENTS.md）に従う。
- **決定 8: 判定器は `scripts/verify-r48.sh` を新設し、層別の full に `r48` を足す。** 47 までの門番は動かさない。

### 仕様への疑義（R48 では決めない）

- **任意の終了コードを返す方法が言語に無い。** `raise` は 1 を返す。`exit(code)` のような操作を足すかは、実際に必要になってから決める。
- **`run` の引数の綴り。** `--` を必須にするかは決めていない。今は `--` が無ければ引数無しとして扱う。
- **一時ディレクトリの寿命。** `run` は実行の後に消す。作り直しを避けるキャッシュは `fmt` と同じく後で考える。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| `hado run main.hd`（`def main = 3`） | 標準出力 `3`、終了コード 0 | §54、決定 4 |
| `hado run main.hd -- a b`（`def main = List.length args`） | 標準出力 `2`、終了コード 0 | §55 の `args`、決定 1、決定 3 |
| `hado run main.hd`（`def main = raise { message = "boom" }`） | 標準エラー `boom`、終了コード 1 | §33、§55、決定 4 |
| `hado run` の入力の隣 | 実行ファイルが残らない | 決定 2 |
| `hado build -o <dir>/x main.hd` | `<dir>/x` ができ、入力の隣にはできない | 決定 5 |
| `hado build` の型エラー | `error[E305]` と `canonical form:`（書き換えがあるとき） | 決定 6 |
| `hado run main.hd -- <stdin>` | 標準入力がそのままプログラムに渡る | 決定 3 |

### 判定

`scripts/verify-r48.sh` を新設し、46・47 の門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** control を先に回す。

- 判定 48-a: `run` が `main` の値を標準出力に出し、終了コード 0 を返す。入力を複数の実行で使っても入力の隣に実行ファイルが残らない（前後でディレクトリの一覧が変わらない）。
- 判定 48-b: `run -- a b c` の引数が `args` にその数だけ見える。数を変えて生成し、期待値は判定器側で数える。
- 判定 48-c: `raise` する `main` の `message` が標準エラーに出て、終了コード 1 を返す。
- 判定 48-d: 標準入力を書いた `main` がそれを読む（`read_stdin` と `Bytes.to_string` の往復）。入力は生成する。
- 判定 48-e: `build -o <path>` がそのパスにだけ実行ファイルを作り、既定の `build` は入力の隣に作る。§58 の文言、`wants.md` の参照、full の層、`run_cli` のテスト、corpus lock。

### スコープ外

- 任意の終了コードを返す言語の操作（`exit`）
- `run` の実行ファイルのキャッシュ
- `hado fmt` と `hado test`
- 効果行付き関数値の `build` 失敗（`docs/bug.md:33`）と `again` の SIGSEGV

### 確認して報告（決定から）

- `run` の後に一時ディレクトリが残らず、入力の隣も変わらないこと（決定 2）
- `Env.args` がプログラム名を含まず、`--` の後の引数だけを見ること（決定 1、決定 3）
- `build -o` が入力の隣に書かないこと（決定 5）
- `build` の失敗に `canonical form:` が出ること（決定 6）

### 中断の条件

**`run` が入力の隣か、その親の根に実行ファイルを残すなら、止めて報告せよ。**

**`run` が子プロセスの終了コードを変える（0 でない終了を 0 にする、または 1 でない終了を 1 にする）なら、止めて報告せよ。**
