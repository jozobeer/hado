# R65 `--format json` の手順書（2026-09-16）（r65）
旧 `docs/plan.md` 61 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/wants.md` の 6（中）「診断を機械可読に」。優先順位 1 の「将来の LSP code action」は診断を機械可読に読む入口が要る。いまの CLI は `Project::report`（`crates/hado/src/project.rs:70`）が人間向けの 1 行を作り、正準形を本文に `; canonical form: <正準形>` として足すだけである。

### 実測した材料

- 整形は `Project::report` の 1 か所。正準形は `canonical_hint`（`project.rs:80`）が別に返す（`fixes::hint` を呼ぶ）。
- CLI の印字は `crates/hado/src/main.rs` の 121・136・167・171 の 4 か所で、いずれも `eprintln!("{}", project.report(&error))` である。印字先は標準エラー。
- `--format` はまだ無い（`grep` で 0 件）。
- `Diagnostic` は `related: Option<Related>` を持ち、`Related` は path / line / col だけである。関連位置のラベルは `parser::related_label(code)` がコードから決める（§56）。
- `Diagnostic.code` は `Option<String>` である（パーサの診断にはコードが無い場合がある）。

### 決定

1. 形は 1 行に 1 診断の JSON（JSON Lines）。診断の順は今と同じである。
2. フィールドは `path` `line` `col` `code` `message` `canonical` `related` の 7 つ。`related` は無ければ `null`、あれば `{path, line, col, label}`。`canonical` は正準形が無ければ `null`。
3. `--format json` は上記 4 か所の診断印字を切り替える。既定は今の 1 行のままで、既存の門番の期待値を変えない。
4. JSON の `message` は素の文面にする。`; canonical form: ...` は本文に混ぜず `canonical` に入れる。
5. 印字先は今と同じ標準エラー。終了コードは変えない（§54 の二値）。
6. `fmt` の `fmt: ...` の行と `test` の `test: ...` の行は診断ではないので対象外とする。

### 期待値の根拠

| 入力 | `check --format json` の 1 行 |
|---|---|
| `def f (b: Bool): Int => if b \| true => 1 \| false => 2` | `{"path": "main.hd", "line": 1, "col": 25, "code": "E520", "message": "use a Boolean branch ...", "canonical": "if b => 1 | 2", "related": null}` |
| 正準形の無い診断（E513 など） | `canonical` が `null` |
| 関連位置のある診断（E205 など） | `related` が `{"path": ..., "line": ..., "col": ..., "label": "first declared"}` |

門番は `json.loads` で読んでから各フィールドを比べる（空白の差で赤くしない）。

### 判定

- 65-a `check --format json` が診断 1 件を 1 行の JSON で標準エラーに出し、`json.loads` で読めて `path` / `line` / `col` / `code` / `message` が一致する。
- 65-b 正準形のある診断（E520）で `canonical` が入り、`message` に `; canonical form:` が混ざらない。
- 65-c 関連位置のある診断で `related` が入り、無い診断では `null`。
- 65-d 既定（`--format` 無し）は今の 1 行のままで、既存の門番（r57 / r62 / r63）が緑。
- 65-e 用法の誤り（`--format yaml`、値を付けない `--format`）は終了コード 2。
- 65-f 文書と層、65-g corpus lock。

### 許容される赤

### スコープ外

- LSP そのもの、`dump-mono` の JSON、SARIF、診断の位置の持ち方の変更。
- スタック溢れを `{Error}` にする（§53.1 が「言語の `Error` ではない」と明記しており、仕様の反転になる。生成コード側のスタック検査が要る）。

### 確認して報告

- `code` が無い診断（パーサ由来）の `code` を `null` にするか省くか。
- `fmt: ...` と `test: ...` の行を JSON に含めない判断。
- `--format` を `check` 以外（`build` / `run` / `test`）にも許すか（今回は 4 か所すべてを切り替える）。

### 中断の条件

- `code` の無い診断が実際に多く、`code` の扱いが決まらないとき。
- `related` のラベルが `related_label(code)` から引けず、`Diagnostic` にラベルを足す必要が出たとき。
