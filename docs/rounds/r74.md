# R74: E511（リテラルパターン）の書き換え（2026-09-16）（r74）
旧 `docs/plan.md` 69 節。実測は `docs/ledger.md`。

## 手順書

### 背景
条件列がすべて同じ変数とリテラルの等値比較（`| x == 1 => … | x == 2 => …`）だと §26 の E511 になる。正準形はリテラルパターンだが、自動修正が無く手で直すしかなかった。

### 実測した材料
- E515 の診断が正準形を綴る: 唯一の引数なら「パターンの腕を直接使う」——`def f` ＋ `| 1 => "one"` / `| 2 => "two"` / `| "other"`。この形は **受理される**（`check` 終了 0。腕を 2 スペース字下げしても 0）。`def f x` の後ろに `if x` を置く形は E100。
- リテラルパターン列は**フォールバック必須**（E402）。したがってフォールバックが無い列は書き換えない。
- 枝ノードの span は `def` 全体（実測: 4:1、範囲に先頭コメントは入らない）。最初の切り落とし位置は `| ` の後ろなので、ヘッダから引数を削るときは末尾の `|` を先に落とす。

### 決定
- 範囲は枝全体（`branch_range(node, Tail::If, …)`）で 1 つ。置換は、ヘッダから共有変数（＝唯一の引数）を落とし、各腕の `x == ` を切り落としたもの。
- 全腕が同じ変数を比べていること、フォールバックがあること、範囲に `//` が無いことを確かめる。
- 歩行器に `NodeKind::CondBranch { arms, fallback, .. }` の腕を足す（この種は誰も所有していなかった）。

### 期待値の根拠
- 期待値はフィクスチャから導く（共有変数を腕に降ろし、`x == ` を落とす）。判定器にサンプルを埋め込まない。
