## 手順書

### 背景
常用 CLI の用法失敗が終了コード 0 で終わっていた。stdlib に `exit` が無いことを穴と見て R76 を立てたが、仕様を先に読むと事情が違った。

### 実測した材料
- `spec.md:1846` 終了コードは 0 と 1 の二値。1 は `raise` が `main` まで届いた場合と印字失敗の場合。区別は stderr がつける。
- `spec.md:1840` `main` が値を返したら stdout に印字して 0。`raise` が届いたら `message` を stderr に印字して 1。
- `spec.md:1389` handler の無い `abort` は `main` の入口で stderr と 1。
- 実測: `raise { message = "boom" }` を `main` に置くと `check-exit=0`、`run-exit=1`、stderr に `boom`。

### 決定
- 言語にも stdlib にも `exit` を足さない（二値の規定に反するため）。失敗は `raise` が `main` まで届く形で表す。
- 常用 CLI の用法失敗を腕の `raise { message = usage }` に変える。
