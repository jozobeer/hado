# R51 実用 CLI を門番の走行に組み込む手順書（2026-09-16）（r51）
旧 `docs/plan.md` 47 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`tools/gates/main.hd` は門番のログを読んで集計する Hado の CLI で、`report/` のライブラリと合わせて既に動く（`hado run tools/gates/main.hd -- target/gates-full-r50` は `3569/3569 passed; red: none`）。しかし `scripts/run-gates.sh` からは呼ばれておらず、判定器の**素材**として使われているだけである（`scripts/run-gates.sh` の 232 行のコメントは「ログは tools/gates/main.hd の集計に混ざるので末尾を `PASSED: n/N` に揃える」と、組み込まれる前提を既に書いている）。目標の優先順位 2 は「自分用の小さな CLI を Hado で常用し、その不足だけを次に足す」である。R51 はこの 1 本を門番の走行に組み込み、常用を始める。`wants.md` の 53。

### 実測した道具の振る舞い

生成したログのディレクトリで測った。`read_dir` は名前を UTF-8 のバイト順で返すので、赤の一覧もその順になる。

| ディレクトリ | 出力 | 終了 |
|---|---|---|
| 空 | `0/0 passed; red: none` | 0 |
| `a.log` が `PASSED: 3/3` | `3/3 passed; red: none` | 0 |
| `a.log` が `1/3`、`b.log` が `2/2` | `3/5 passed; red: a.log` | 0 |
| `passed` 行の無い `.log` | （stdout 空、stderr は `InvalidLine`） | 1 |
| `PASSED:` の無い `notes.tsv` | （stdout 空、stderr は `InvalidLine`） | 1 |

**入口の契約: ディレクトリの全ての項目が `PASSED: n/N` の行を持つログでなければならない。** これは緩めない。走行のログは走行自身の成果物で、Hado がそれを読めないなら走行の欠陥だからである。

### 決定

- **決定 1: `scripts/run-gates.sh` の最後（`lint-docs` の後）に集計を出す。** 走行のログを Hado の道具で数える。bash 側で数え直さない（数え方が 2 つあると食い違う）。
- **決定 2: 集計の行は `TALLY: <出力>` として標準出力に出す。** 出力先ディレクトリには書かない。集計自身が読むディレクトリなので、自分のログを混ぜると入口の契約を破る。
- **決定 3: 集計が失敗したら走行を赤にする。** ログが読めないのは走行の欠陥である。既に赤の走行では赤のままなので、増える赤は「ログが不完全」という情報になる。
- **決定 4: 集計は層と選択に関わらず走らせる。** どの走行でもログは出るので、quick でも選択だけの走行でも出す。`hado` のバイナリか `tools/gates/main.hd` の無い走行（判定器が作る合成木）では黙って飛ばす。成功した走行が stderr に何も書かないことは `verify-r38.sh` と `verify-gate-cache.sh` が固定している契約で、`TALLY:` の行が無いこと自体が印になる。**最初の実装は飛ばす理由を stderr に出し、この 2 本を赤にした。門番を緩めずにこちらの決定を変えた。**
- **決定 5: `hado` は `${CARGO_TARGET_DIR:-target}/debug/hado` を使う。** 他の門番と同じで、PATH を探さない。
- **決定 6: 判定器 `verify-r51.sh` を新設し、層別の full に `r51` を足す。** 判定器は生成したログで道具の集計を測り、走行への組み込みは合成木で測る（`verify-r38.sh` が `run-gates.sh` を測るのと同じ形）。判定器に門番の名前や本数を書かない。
- **決定 7: 仕様は変えない。** `tools/gates` はリポジトリの道具で、言語仕様の外にある。

### 仕様への疑義（R51 では決めない）

- 出力先ディレクトリに前の走行のログが残っていると、その走行のログとして数える。`run-gates.sh` は出力先を消さない。消すかは、部分走を繰り返す使い方が固まってから決める。
- `HADO_GATE_TIMES` を出力先の中に向けると、`.tsv` が入口の契約を破って集計が赤になる。記録先は走行のログの外に置く。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| 空のディレクトリ | `0/0 passed; red: none`、終了 0 | 実測（表） |
| 全て緑 | `合計/合計 passed; red: none`、終了 0 | `report::Report.add` |
| 赤を含む | `合計/合計 passed; red: <名前>` を名前のバイト順に | `read_dir` の順と `merge` の順 |
| `PASSED:` の無い `.log` | 終了 1、stderr に `InvalidLine` | 実測（表） |
| 合成木の門番 1 緑 1 赤 | `TALLY: 1/2 passed; red: verify-stub-b.log`、走行は赤 | 決定 1、決定 3 |
| 合成木の門番が `PASSED:` を書かない | `TALLY: failed (...)`、走行は赤 | 決定 3 |

### 判定

`scripts/verify-r51.sh` を新設し、50 までの門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** control を先に回す。

- 判定 51-a: ログのディレクトリを生成し（本数 0〜5、`passed <= total`、緑と赤を混ぜる）、道具の出力が判定器の計算した合計と赤の一覧に一致し、終了 0。集計がディレクトリに何も書かないこと（走行前後の一覧が同じ）。
- 判定 51-b: `PASSED:` の無い `.log`、`PASSED:` の無い非ログ、`Int.parse` の失敗（`PASSED: 1/x`）、引数無しの 4 形。終了 1 と stderr の内容。
- 判定 51-c: 合成木で `scripts/run-gates.sh --jobs 1 --tier full <出力>` を走らせ、`TALLY:` の行が判定器の計算と一致すること。緑と赤の門番、`PASSED:` を書かない門番の 2 通り。
- 判定 51-d: full の層に `r51` があり、`wants.md` の 53 が更新され、corpus lock が緑。
