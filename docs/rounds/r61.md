# R61 再帰定義の省略した効果行の手順書（2026-09-16）（r61）
旧 `docs/plan.md` 57 節。実測は `docs/ledger.md`。

## 手順書

### 背景

`docs/bug.md` の最後の 1 件「効果行を省いた再帰生成器が E306 になる」（R35、裁定 #11）。R35 の台帳は原因を未調査のまま先送りし、それから 25 ラウンド残っている。優先順位 3「check は通るが実行できないをなくす」の逆側で、正しいプログラムを拒否する穴である。

§20 は「行は書かなくてよい。書かなければ推論に任せ、暗黙の効果変数として全称量化する」と定めている。§9 は E307 を「再帰呼び出しにおいて、引数の型と仮引数の型の単一化が出現検査に失敗した場合」に限り、「それ以外の出現検査の失敗は E306」としている。この 2 つを合わせると、効果行を省いた再帰定義は受理され、行は推論されて効果変数として全称量化されるのが仕様である。したがってこれは実装の不具合で、仕様の疑義ではない。

### 実測した材料

リポジトリルートで、その場で書いたプログラムを `cargo run --offline -q -- check` に渡した。

| 書いた形 | いまの出力 |
|---|---|
| `def rec generate (n: Int): Int List =>` の本体が `n % 7` と再帰呼び出し（bug.md の形） | `main.hd:1:1: error[E306]: cannot unify A with Fn(Int => Int List {Error | B})` |
| 同じで戻り型を `Int List {Error}` と書く | 無診断、終了 0 |
| 再帰を外す（`def f (n: Int): Int List => [n % 7]`） | 無診断、終了 0 |
| 再帰のまま、効果を呼び出しから得る（`def g … {Error}` を呼ぶ） | `main.hd:2:1: error[E306]: cannot unify A with Fn(Int => Int List {Error | B})` |
| 再帰のまま、リストを使わない（`n % 7 + f (n - 1)`） | `main.hd:1:1: error[E306]: cannot unify A with Fn(Int => Int {Error | B})` |
| 再帰のまま、本体が純粋（`[n, ...f (n - 1)]`） | 無診断、終了 0 |

再帰と効果の両方が要る。効果の出どころ（`%` か呼び出しか）は問わない。

計測器を `unify` の E306 の枝に置いて変数を同定した（あとで外した）。

```text
DEBUG occurs at 1:1
  a=Var(896)  ra=Fn([Int], Adt("List", [Int]), Var(897))
  b=Fn([Int], Adt("List", [Int]), Open(897, [Adt("Error", [])]))
```

`a` は群の先頭で入れた定義のプレースホルダ（Var 896）で、既に再帰呼び出しの単一化で `Fn([Int] => _ {Var 897})` に束縛されている。`b` は本体の推論結果で、行が `{Error | Var 897}` である。同じ Var 897 が、定義の行と本体の行の末尾の両方に現れるので、最後の単一化が `897 = {Error | 897}` を要求し、出現検査に落ちる。

`--print-type=generate` は、直したあとで `Fn(Int => Int List {Error | A})` を出す（非再帰の `def f (n: Int): Int List => [n % 7]` も同じ開いた行を出す。省略した行は非再帰でも開いて出るのがいまの振る舞いである）。

### 決定

1. 再帰呼び出しの効果の行を、呼ばれる定義の行と同一化しない。呼び出しの効果はその呼び出し自身の新しい行とし、定義の行は本体の効果の行（群の最後の単一化）で決める。§20 の「暗黙の効果変数」はこうして現れる。同じ定義への 2 度目以降の再帰呼び出しも同じ扱いである。
2. 書いた行の検査は変えない。本体の推論結果と書いた行の包含の検査（`contain_row`）はそのままなので、`{Io}` と本体の `Error` は E305 のままである。
3. E307 の機構は変えない。E307 は引数の型の出現検査で、行には触れない。
4. 仕様は変えない。§20 が既にそう書いている。コードも足さない（E306 のまま）。
5. `docs/bug.md` の当該の節を削る（直ったので）。

### 期待値の根拠

| 入力 | 期待 | 根拠 |
|---|---|---|
| bug.md の形（省略した行、再帰、`%`） | 受理。build して実行すると `5` | §20。材料の 1 行目 |
| 相互再帰で両方の行を省略 | 受理 | §20 と同じ。呼び出しの相手が群の別の定義でも同じ |
| 戻り型を `Int List {Error}` と書く | 受理 | 材料の 2 行目 |
| 戻り型を `Int {Io}` と書き、本体が `Error` を出す | `E305`（効果行の食い違い）のまま | §20 の「書いた行はその通りの意味である」 |
| 省略した行にユーザー効果があり、main が囲まない | `E706`（main はユーザー定義の効果を持てない） | 効果は消えない。推論された行が main まで届く |
| 同じで main が handler で囲む | 受理。実行すると `15` | 同上。行が使える形で届く |
| `def rec poly x => poly [x]` | `E307` のまま | §9 |
| 受理コーパスと拒否コーパス | 変わらない | 行を書いた定義には触れない |

### 判定

- 61-a bug.md の形: `check` が受理し、`run` が `5` を出し、終了コードが 0。
- 61-b 切り分け: 非再帰は受理、相互再帰（両方とも省略）は受理。
- 61-c 書いた行は効く: `{Io}` と `Error` は E305、`{Error}` は受理。
- 61-d 効果は消えない: 省略した行のユーザー効果は main で E706、handler で囲むと実行して `15`。
- 61-e E307 は残る: `def rec poly x => poly [x]` は E307。
- 61-f コーパスロック: `sha256sum --strict --status -c tests/corpus.sha256`。

### 許容される赤

- 実装前の 61-a、61-b、61-d の赤（61-c と 61-e は実装前から緑である）。

### スコープ外

- 推論された行の精度。省略した行は非再帰でも `{Error | A}` と開いて出る。これを閉じた最小の行にすることは、行の既定化の設計そのもので、このラウンドでは触らない。
- 行の全称量化の表し方（スキームの量化にどう載るか）。
- E305 の文面、書き換え、`fmt`、`explain`、`--format json`。

### 確認して報告

- 省略した行が再帰で開いて出ること（`Fn(Int => Int List {Error | A})`）が §20 の「全称量化」として足りるか。
- 相互再帰の群で、行がどのように閉じるか（今回の実装で受理はするが、開いた行が呼び出し側にどう届くか）。
- この変更で受理が広がる範囲。効果が消えていないことを 61-c と 61-d で測っている。

### 中断の条件

- 省略した行のユーザー効果が main まで届かなくなる（61-d が赤）とき。
- 書いた行の検査（E305）が緩むとき。
- 受理コーパスが赤になるとき。
