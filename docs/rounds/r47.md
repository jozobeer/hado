# R47 正準形の修正を E515 と E501 へ広げる手順書（2026-09-16）（r47）
旧 `docs/plan.md` 43 節。実測は `docs/ledger.md`。

## 手順書

### 背景

R46 の `check --fix` は E510 / E516 / E517 を直す。残る日常的な正準形の拒否は E515（`def f x => if x | ...` の引数を腕へ移す、§31）と E501（`let x = v -> x` の同一束縛、§41）である。どちらも `docs/wants.md` の「診断と正準形」1 が挙げている。R46 の `Fix` の一覧と適用器をそのまま使い、規則を 2 つ足す。

E515 の書き換えは R46 の 3 つと違い、範囲が 2 つの綴り（引数と `=> if <scrutinee>`）にまたがる。型注釈の無い引数は括弧を取らない（`def f (x) =>` は E100）ので、範囲の始まりは引数の名前である。`fn(| ...)` の形は範囲が違うので R47 では直さない（診断はそのまま出る）。

E501 の分離点は、値の式に `->` が入れ子で現れ得る（`let x = let y = 1 -> y -> x`）ため字句の走査では決まらない。AST の本体の位置の 1 つ前の `->` を使う。

### 決定

- **決定 1: E515 の条件は検査器と同じ関数にする。** `check_sole_parameter_branch` の構造判定を `crate::check::sole_parameter_branch` として切り出し、検査と修正の両方が同じ述語を使う。条件は「引数 1 つ・型注釈なし・戻り型なし・`$argument` でない・本体が 1 つの scrutinee のパターン分岐・scrutinee が引数名・引数が腕から参照されない」。
- **決定 2: E515 の範囲は「引数の綴りの直前の空白から scrutinee の綴りの終わりまで」を消す。** 型注釈の無い引数は括弧を取らないので、始まりは引数の名前の綴りである。置換は空文字列。正準形は `def f | ...`（`rec` を保つ）で、`source_print` に引数名を `$argument` にした写しを印字させる。
- **決定 3: E501 の範囲は `let` から本体の名前の終わりまで。** 置換は `=` の直後から本体の直前の `->` までのソース（前後の空白を除く）。分離点は本体の位置の 1 つ前の `->` トークンで決める。`pat` と本体が同じ名前の `NodeKind::Let` だけを対象にする（`LetQ` と `do` は対象外）。
- **決定 4: コメントを消さない規則は R46 と同じ。** 範囲に `//` を含む `Fix` は出さない。E515・E501 の置換の範囲にも当てる。
- **決定 5: E507・E508・E502・E503・E505 は R47 の対象外。** 直せない診断は今まで通り停止して報告する。
- **決定 6: 判定器は `scripts/verify-r47.sh` を新設し、層別の full に `r47` を足す。** 46 の門番は動かさない。仕様 §57 の書き換えの一覧に E515 と E501 を足す。

### 仕様への疑義（R47 では決めない）

- `fn(x) => if x | ...` の E515 は直さない。`fn(| ...)` の正準形の範囲が `def` と違うためで、`fn` の書き換えを入れるときに決める。
- E501 の置換は値のソースをそのまま移す。値の外側の空白は落ちる。レイアウトをどこまで保つかは `fmt` で決める。

### 期待値の根拠

| 形 | 期待 | 根拠 |
|---|---|---|
| `def f x => if x \| Some(v) => v \| 0` | E515。`--fix` の後は `def f \| Some(v) => v \| 0` | 決定 1、決定 2、§31 |
| `def f (x: Int) => if x \| ...` | E515 は出ない（型注釈あり） | §31、E100 |
| `def f x => if x \| Some(v) => x \| 0` | E515 は出ない（腕が引数を参照） | §31、決定 1 |
| `def main = let x = 5 -> x` | E501。`--fix` の後は `def main = 5` | 決定 3、§41 |
| `def main = 1 + (let x = f 2 -> x)` | E501。`--fix` の後は `1 + (f 2)` | 決定 3 |
| `def main = let x = let y = 1 -> y -> x` | 内側の E501 から直り、次に外側が直る | 決定 3、R46 決定 2 |
| 範囲に `//` を含む形 | `Fix` を出さず、ファイルは変わらない | 決定 4 |

### 判定

`scripts/verify-r47.sh` を新設し、46 の門番はそのまま回す。**入力は生成し、期待値は判定器側で計算する。** control を先に回す。

- 判定 47-a: E515。乱数の 1 引数関数を `def f x => if x | p => v | fallback` の形で生成し、`check` が E515 と `canonical form:` を出し、`--fix` の後は `def f |` の形で、コメントが残り、`build` の実行結果が判定器の計算と一致し、2 回目の `--fix` がファイルを変えない。
- 判定 47-b: E501。乱数の値の式（リテラルと関数適用）を生成し、`--fix` の後はその式だけになり、実行結果が一致する。
- 判定 47-c: E501 の入れ子（`let x = let y = ... -> y -> x`）が内側から順に直る。
- 判定 47-d: コメントを含む E515 / E501 の範囲ではファイルが変わらない。
- 判定 47-e: §57 が E515 と E501 に触れ、full の層に `r47` があり、`cargo test --offline -q --test r47_fixes` が緑で、corpus lock が緑。

### 中断の条件

**E515 の書き換えが、腕が引数を参照する形（`def f x => if x | Some(v) => x | 0`）を書き換えて意味を変えるなら、止めて報告せよ。**

**E501 の書き換えが、値の入れ子の `let` を分離点と取り違えて壊れたソースを書くなら、止めて報告せよ。**
