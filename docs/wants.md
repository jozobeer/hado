## 診断と正準形

正準化は一つの関数（正規形印字）。linter は置かない（2026-09-10）。レイアウトと一意な意味保存の書き換えは `hado fmt` が書く（R52 で書き換えの一括適用を入れた。レイアウトの正規化は `docs/issues/fmt-layout.md`）。未使用は直さない。既定の `check` / `build` は読んだファイルを変えない。`hado check --fix` が編集ループ（先に fmt してから検査）。`build --fix` も同じ関数を先に走らせる。

1. **高** 冗長の診断に正準形を出す。正規形印字が既にあるので、E515 / E517 / E510 / E501 などは「こう書け」をソースとして足せる。R46 で E510 / E516 / E517、R47 で E515 / E501、R57 で E507 / E508、R62 で E503、R63 で E520 を足した（§24、§29、§57、`docs/rounds/r46.md`・`docs/rounds/r47.md`・`docs/rounds/r57.md`・`docs/rounds/r62.md`・`docs/rounds/r63.md`）。残りは未使用（直さないと決めている）と、形が局所でない E502 / E506 / E511 / E512。腕が 1 本だけの条件列（§24）も残り。残りの 4 つのアンカーと節を実測した（エラー表の行）: E502 は `if`（§42、第32節の形では `def` か `fn`）、E506 は `_`（§40）、E511 は `if`（§26、第32節の形では `def` か `fn`、腕の条件列）、E512 は変数パターン（§26）。`check.rs` の `catch_all_row`（436 行）が、腕の全部の pattern が `_` か変数で、どれかが変数のときに出す（全部 `_` なら E503）。再現は `type T = | A | B` と `def f (t: T): T => if t | A => A | y => y` と `def main = f A` で、`main.hd:2:36: error[E512]`。正準形は fallback だが、束縛を使う本体は scrutinee に置き換える（`| y => y` を `| t` に）。その形は E507 を出す（branches reconstruct the value）が、`hado fmt` は書き換えない（実測: `fmt` は何も出さず、行は `if t | A => A | t` のまま。R57 の E507 の書き換えは fallback がある形を避ける）。したがって E512 を fallback に書き換えるだけでは E507 の診断が残るので、E512 の書き換えは条件ごと scrutinee に畳む（`if t | A => A | y => y` を `t` に）ところまで行く必要がある。書き換えは本体の複数箇所を置き換えることになるので（fixes は重ならない複数の編集を持てる）、scrutinee が単純な変数のときだけに限るのが安全である。E502 は条件の効果、E506 は束縛の形、E511 は腕の文脈が要る。

## 後回しの核

汎用と衝突するもの。優先度は付けない。

- 並行プリミティブ — サーバ、並列コンパイル。`async` / await は置かない。入れるなら効果。`again` はジェネレータ相当のまま
- mutation — 破壊的更新が本体の構造。不変配列の `set` で足りなくなったら `State` 効果であり、代入構文ではない
- first-class module — 実行時に型を隠したプラグイン。閉じた ADT か効果。両方同時は持たない
- FFI — 54。OS と C
- GADT — 型付きインタプリタ。無くてもコンパイラは書ける
- 幽霊型 — 単位や状態機械。`type A T = Int` は E518。必要になってから緩める（計画 13.3）

## 足さない

- 冗長を warning に落とす（緩和は規則から外す）
- 独立した linter。既定の `check` / `build` がソースを書き戻す。未使用の auto-fix
- 部分適用、型の別名、マクロ、暗黙変換、演算子過負荷
- List の中間展開（11.3）
- 設定ファイルで根を探す（13.3）
- 親ディレクトリ名の無修飾参照（13.3）
- `U8` 型（バイト処理は Bytes）
