# issue の置き方

`docs/issues/` は、次にやる候補を 1 件 1 ファイルで置く場所である。`docs/wants.md` は思いついた順の一覧で、根拠と完了条件が揃った項目をここへ移し、`docs/wants.md` からは消す。issue の由来欄に元の番号を残す。

## 識別子

slug の字種は `docs/rounds.md` と同じ `[a-z0-9][a-z0-9-]*` で、`r<数字>` の形は使わない。着手したら同じ slug で `docs/rounds/<slug>.md` とブランチと worktree を切る。issue とラウンドの対応はファイル名だけで付く。`docs/plan.md` の版ごとの決定は一時的な issue のパスではなく slug を識別子にする。着手後の手順と実測は同じ slug のラウンドファイルが持つ。

## ファイルの形

```
# <題>（<slug>）
優先度: 高|中|低。
## 現象
## 原因
## 案
## 完了条件
## 由来
```

現象は実測（コマンドと出力の末尾）をコードフェンスか表で置く。案は候補を並べて推奨を 1 つ選ぶ。完了条件は門番で測れる形に書く。由来は `docs/wants.md` の番号と仕様の節である。現象のフェンスか表、原因のパスと識別子、節番号、エラーコードは `scripts/lint-docs.sh` が検査する。

### 参照の書き方（2026-09-18）

原因は行番号を書かず、`` `パス` の `識別子` `` で場所を指す（`path:line` と `:line` はどちらも赤になる）。識別子は `fn`・`def`・`const` の名前や `re.compile` の変数名など、そのファイルで場所を絞れる名前を選び、同じパスの識別子は続けて書いてよい。門番はパスの実在と、そのファイルに識別子が出現することを見る。仕様は `§N`（`§26.1` も可）、付録は `付録C`、エラーは `E602` で指し、門番が仕様の見出しとエラー表に実在することを見る。参照は語の全体で照合し、`§55x`・`付録Cfoo`・`E100foo` のように続けて書いたものは参照として読まない。

### 実測のフェンスの約束（2026-09-18）

`$ ` で始まる行をコマンド、`> ` で始まる行をコマンドの続き（PS2）とする。`#` で始まらず、プレースホルダ（`TBD` `TODO` `...` `未計測` など）でもない空でない行を出力とする。門番はフェンスの中にコマンドと出力が 1 行ずつ以上あることだけを見て、シェルの文法（継続・heredoc・置換・複文）は解析しない。コマンドと出力の対応、heredoc の本文、`> ` の行が出力に混ざっていないかはレビューで見る。

フェンスは行頭に置き（字下げしない）、表は引用の外に置く。範囲は `-` で書き、en ダッシュは使わない。原因には URI（`scheme://…`）を書かない。

```
$ cargo run --offline -q -- check tests/reject/E100/main.hd
error[E100]: ...
```


## 消し方

着地したら issue を消す。実測はラウンドファイルが持ち、経緯は git 履歴が持つ（`docs/bug.md` と同じ）。退けたときも消し、理由をコミット本文に書く。

## 数えない

件数と一覧は書かない。`ls docs/issues` が一覧である。
